# IDOL Production System

This is the compact target Graph Engineering routing map. It remains
`shadow_not_default`: existing and new runs stay legacy-pinned until a verified
atomic default-switch receipt. Historical `harness-*` ids become parse-only
Legacy Capsule inputs only after that switch. Read this for stage and ownership, then
load the complete owning skill, active schema, activated policy, and current-run
sources. Artifact and command detail lives in
[`production-system-detail.md`](production-system-detail.md); this page does
not duplicate that procedure.

## Studio Model

Exactly one Founder-selected registered Cursor or Grok surface is the Overall Director for
the run. It owns routing, canonical promotion, Founder recommendation, and
final creative acceptance. Physical Overall succession is primary plus
successor, maximum two, per macro-stage. In Graph v2, before G-40 it opens Founder-visible
Creative Development Director (CDD) lanes as a Planning CDD Cell: P1 Story/Audience Lead and only planning integration writer,
P2 Visual/Reference Development, and P3-C1..Cn Section/Kinetic Architecture,
one lane per contiguous 2--3-section cohort. At G-40 that Cell becomes a
read-only handoff and the exact P3 `section_cohort_id` is carried into
V-C1..V-Cn, one Section-Cluster CDD per the same cohort through 02B pixel and
03V playback review. Each CDD lane/stage allows primary plus successor,
maximum two physical sessions.
There is no standing Final Director and Terra is not an ordinary creative route.
Until the switch, the legacy-pinned route keeps exactly one durable
compatibility CDD through 03V and never co-runs the Graph lanes below.

Clear ownership, exact hashes, and source evidence prove only stated facts
and cannot weaken Director or Founder pixel and playback judgment. Graph
Director succession is a lane-local shadow-readiness model, not a new Founder
gate or execution authority. On Graph v2 the registered router keys state by
`lane_id + macro_stage_id`, represents one read-only successor after typed-core
provider-native Goal evidence, and models a one-writer CAS. It always returns
`HOLD` until typed transition receipts and a freshness-enforcing execution
consumer exist. Disjoint lanes may coexist. Legacy-pinned CDD router and
receipts stay separate; the two routers never share a state file or active
writer.

## Active Route

The Graph v2 branch below is the verified-switch target; legacy-pinned authoring
remains the active writer until that switch.

```text
Founder G0 input
-> one logical Overall Director lineage
-> PRE-00 audience + trend evidence -> Founder target/promise/message lock
   -> immutable full natural-language MV storyline original + append-only
      full-text revisions/reference receipts -> v3 exact-copy handoff
-> Planning CDD Cell until G-40: P1 Story/Audience, P2 Visual/Reference,
   P3-C1..Cn Section/Kinetic (one contiguous 2--3-section cohort each)
   -> one Founder-visible Song Room under the Planning Cell -> selected audio
      -> audio-motion map -> 00A
-> whole-work Section Dispatch Map
   -> only disjoint video/still/Pinterest assignments needed for named gaps
      (provider-native helpers stay inside the parent Work Package; media/long
       context/independent outputs may start in a physical session)
   -> conditional current-title Member Visual Identity room when a card is missing/new/restyled
   -> disjoint bounded pre-02A development blocks under backpressure
-> Front Planning + 01R / optional 01R-C
   -> exactly FP-A/B/C + MJxx Major Stacks + 2--4 Sequence/Core candidates
   -> exact Core reference coverage + representative/risk Hero proof -> G-30
   -> Founder G1 planning route
-> 01 one-image Official Cores -> 02A imported-Core Branch-only plan
   -> 02A Draft Keyframe Proof + audio hard-cut animatic -> Founder G2 -> G-40
-> Planning Cell read-only handoff; exact P3 section_cohort_id carried into V-C1..V-Cn
-> roster-derived Section-Cluster CDDs; partitions 2 or 3 only
   (4=2+2, 5=2+3, 7=2+2+3, 8=2+3+3, 9=3+3+3; singleton only for one-section titles)
-> fresh exact-one-section lineage: provider-neutral 02B/Cut image -> G-50
   -> provider omitted: current Grok session `image_gen`/`image_edit` on the
      Grok CLI Section owner; Cursor Luna image is explicit-only and opens
      only when the Founder names it, then transfers through the registered
      Luna-to-Grok CAS after pixel review; explicit APIs remain separate
      and never fallback
   -> same-cohort 03V successor: placement -> Core/Branch Motion Storyboard
      -> 480/720 playback -> that Section-Cluster CDD
-> Overall cross-cohort whole-film review
-> fresh Founder-visible Edit Director -> disjoint Edit shards when needed -> 04 merge/QC
-> Founder G3 reviewed section playback
-> mandatory 04FX transition-opportunity audit (may close `complete_no_fx_needed`)
-> 05 master/release package -> Founder G4
```

There is no active 00, 01A, or 02 creative artifact. Build one coherent
full-song MV graph first. Every material Major requires real contiguous
motion evidence. Active reference roles are at most `character_visual`,
`scene_visual_package`, `motion_reference`, and optional `prop_reference`.
Recover a bound unit by `source_id` → locator → function/role → disposition
(`applied` / `combined` / `held` / `rejected`) → section/Major/Core binding →
02A Branch / 02B packet / 03V motion storyboard, using `source_id`, locator,
and SHA-256. Wiki is a routing summary, not a second media library; default
packs and this page exclude raw URL lists. A Founder-selected coherent teaser may enter physical
production before held full-MV scope, but the two states remain independent and
reuse the same lineage. Publishing, platform upload, analytics,
and memory promotion are separate post-05 operations routed to
`wiki/social-automation-system.md`. Studio dashboard and secretary work
(Notion, Drive `IDOL_STUDIO`, Grok Bot, Slack) routes to
`wiki/idol-studio-ops.md` and is never ordinary MV load. Teaser starts at
`teaser/AGENTS.md`. CF history is frozen under the `AGENTS.md` archive rule;
do not run CF operations.
No Major Scene, Core Cut, 02A, or other mid-pipeline videoization route exists;
motion execution remains behind the post-02A image pass and 03V.

|---|---|
| Run authority | Overall: routing, promotion, whole-video judgment, final acceptance |
| Planning through G-40 | Planning CDD Cell: P1 integration, P2 visual/reference, P3-Ci section/kinetic Decision Sets; milestone to Overall |
| Production through 03V | Section-Cluster CDD V-Ci: same `section_cohort_id` as P3-Ci; integrated Cut/Motion Storyboard/playback review; milestone to Overall |

| Reusable source analysis | source-hub owner: registration and Layer A/B evidence only; never run disposition |

| Front Planning / 01 / 02A | Planning CDD working synthesis and shard review; 01 owns Cores, 02A owns Branches; Overall promotes |

| 04 / 04FX | fresh Founder-visible Edit Director; Edit shards and bounded finishing work return only to it, merged package to Overall |

The root may perform a provider UI create action, but that mechanical action
never changes logical ownership or return recipient.

Provider-native helpers are available to a parent Work Package by default but
never gain a logical role, canonical owner/writer, Founder dialogue, promotion,
paid, or external authority. A physical session is chosen from the start for
media, long context, independent output, or lifecycle evidence when more
effective. One Work Package never has simultaneous internal and physical owners.

## Front Planning And Reference Wave

Front Planning is the canonical Founder-facing planning report. It carries the
locked target/message, whole-video progression, title identity, section jobs,
member allocation, exactly FP-A/B/C, ordered `MJxx` Major Stacks, reference
dispositions, 2--4 complete Sequence compositions per material Major, 2--4
actual still candidates and one selected exact reference per material Core Slot,
Hero proof, and entry/exit continuity. 01R and optional 01R-C are substages.
Each visual section binds at least one exact-five same-event Sequence Unit at
exact one-second cadence with five observations, contextual flow reading,
manifest and paths/hashes. Longer flow uses linked Units. Legacy three-second
Units are read-only and never upgraded. A contact sheet counts as zero.
A section may hold several events; Major count has no global cap. Front
Planning expands the PRE-00 original as an append-only full-text descendant,
plants Majors in that expansion, marks Cores from those Sequence sheets, and
adds further Cores or Majors when the Founder kinetic start needs another
must-remain still for the named 2--3 second transition tendency. Machines do
not count seconds. Sequence is
the Major parent sheet. One event typically leaves one or two key Cores on that
sheet, not a start / middle / end set, and five Sequence frames are never five
Cores. New G-30 cycles show the sheets on top with those Core marks; a still
gallery does not replace Major. New authoring uses that layer inside this
existing stage order. Frozen COLOR STAY G-30 bytes stay until an exact Founder
reproject sentence.

After song and section boundaries exist, the Planning CDD Cell dispatches only assignments needed
for named gaps. Generalists use registered role/media checkpoints and return curated
Decision Set deltas, never raw pools. World/Still never searches, opens,
downloads, samples, screenshots, or extracts video; every comparison of two or
more stills—including pruning and CDD/Founder review—uses the required
hash-bound uncropped contact sheet while individual image/crop paths and hashes
remain the actual units. Pinterest remains a registered eligible source; it does
not create a stage, identity lane, per-section quota, or automatic attachment.
Review backpressure, single-writer ownership, and actual graph gaps determine
scheduling.

If a required current-title member card is missing, new, or fully restyled,
the Planning CDD Cell opens one conditional physical Member Visual Identity room. It works
members sequentially, keeps face-only as the sole facial-identity source, and
returns candidate media and evidence to P2. A passed card binds directly and
does not reopen; no separate background/world asset package is created, though
a section- or Cut-scoped `scene_visual_package` may compile world/look and
still composition.

## 01, 02A, And Post-02A

Pre-02A development owns one section by default or two to three connected
sections when they share one mechanism; each return still has separate section
rows, floors, boundaries, and holds. 01 expands observable action/hold,
staging, relation, world/object response, transitions, references, and
still-camera geometry and every Official Core with one passed primary image.
02A imports Core bytes unchanged and owns ordered `1..N` Branch Cuts, their
exact member/reference bindings, composition, and continuity; it
does not author temporal camera movement. It does preserve motion-ready still
conditions—axis/screen direction, lead or reveal room, depth layers, a
physically legible path or occlusion, crop safety, and the adjacent continuity
carrier—inside existing camera/composition/continuity prose. 02B renders those
visible prerequisites, and 03V chooses actual movement, speed, envelope,
reveal/stop, and edit handoff only after pixel inspection.

Exact G-40 approval opens a fresh exact-one-section lineage under the
Section-Cluster CDD that carries that section's P3 `section_cohort_id`. It owns one
five-line packet/request/one-image output per authorized Hero/Core/Branch Cut,
pixel review, audio placement, Core/Branch Motion Storyboard, 03V, and playback
handoff to that same V-Ci CDD. It never loads another section, raw pools, or pre-02A chat.
Render correction opens only for a named pixel hold in that same lineage.

04 starts only from passed 03V playback and the edit-owner contract. Edit
Director owns the canonical edit map and whole-video merge; Edit shards are
disjoint advisory/working units and never become final edit truth.

## Dispatch, Context, Review, And Revision

Every delegated task binds the Department Dispatch Contract, exact skills and
linked EOF reads as a mechanically validated dependency inventory, Founder
epoch/locks, input digest, owner/write scope,
permissions, output paths, stop conditions, and return recipient. Overall owns
the whole-stage route from startup and assigns the one CDD room for each
Planning lane or section cohort its current
checkpoint; it does not replace that CDD each assignment. CDD/FP/02A multi-leaf
parent-scoped helpers and the post-song reference worker fetch floor are in
`automation/harness-execution-contract.yaml` `session_and_helper_operating_lock`.
That CDD owns the film (storyline, target, references, members,
section jobs) inside its lane or cohort through 03V and transmits the complete job. A worker receives
that job and does not load the whole graph-engineering route. Keep the whole-film route
as film truth: Overall for stage legality, cross-cohort promotion, and
whole-video judgment; each CDD for the film inside its lane or cohort
through 03V. The shared
provider-neutral Studio Kernel supplies the fixed twelve-block command and the
selected profile/checkpoint; after native Goal admission, the deterministic
projector verifies the registered source closure to EOF and emits one exact
`idol-role-context-pack.v1`. The receiver applies that pack plus the named
current creative sources. This replaces broad runtime instruction rereads and
does not become an additional authority or prompt layer. The director authors
the Current Assignment Delta; repeated method is reused from the registered
recipe and not copied into a manual provider prompt.

If the current run has a valid v3 Founder-feedback sidecar, the same pack also
projects only the exact role/profile/stage/section-matching compact quality
patterns. CDD/Overall/Edit receive the current-run review view; workers receive
their exact section view. Each pattern carries a short reason, recurrence
count, bounded positive/avoid/action/review signals, and source sidecar digest,
never the raw Founder quote or transcript. This semantic edge helps the
receiver judge the current output but creates no lock, gate, automatic taste
rule, or creative PASS.

When physical Git isolation is useful, `wiki/artifact-management-system.md`
projects the same single-writer Dispatch as `main -> run integration -> bounded
lane worktree`. A Git lane is optional transport, not a stage or creative
branch, and its accepted diff returns only to the named Director before the run
integration branch can reach `main`.

CDD and workers wait for `final`, `hold`, `authority_request`, or `milestone`;
the wake payload is pointer-only (output/manifest, decision, risk, and hashes),
never raw commentary. `returned` is not PASS: CDD closes worker requirements against the pack, named
current-run sources, the same checkpoint closure cards, and the exact returned
bytes; then Overall reviews the curated milestone and promotes sequentially. A
multi-file return exposes one aggregate manifest with exact child paths and
SHA-256 values. Dispatch records stay at
`RUN/work/department-dispatches/DISPATCH_ID.yaml`; outputs and manifests stay
inside that same album/title/run, never a global `runs/workers` lane.

A review cycle has at most three total submissions, including the initial
return. `review_submission.submission_number` is separate from
`lineage.attempt_number`, so normal checkpoint progression remains uncapped.
After a non-accept review, the Director returns one complete correction unit
with all observed problems, exact invalidated output hashes, correction action,
and acceptance criteria. Submission 2 or 3 opens a new immutable attempt and
native Goal for only those invalidated paths; unaffected outputs are
hash-frozen. Thus one failed cut in a ten-cut return reopens only that cut. A
third submission may pass; otherwise it routes upstream or HOLD and cannot open
a fourth child submission. Session, provider, model, or Founder-epoch changes
do not reset the same work package. Unchanged input/result bytes and Founder
epoch still reuse the same review receipt.

The three-submission limit applies to creative returns, not receipt repair.
Corroborated hash-only drift closes through one run-local mechanical refresh
receipt, with no worker session, native Goal, semantic re-review, or submission
increment. A real input-byte change routes once to the original recipient
Director for an impact decision before any worker is reopened; changed output
bytes remain a quality HOLD. This prevents one solved job from circulating
between workers solely because a duplicate hash field disagrees. The aggregate
return shows one transport-closure summary; raw receipts stay folded unless an
unresolved error changes Director action.

All visual decisions use one cumulative `idol-html-review-board.v12` G-00--G-70
lineage. Route a
change to the smallest owner—Front Planning for central locks, 01 for section
direction/Core, 02A for Branch/composition/binding, image packet for render wording,
exact output for pixels, 03V for motion, and 04 for edit—and invalidate only
affected descendants.

## Graph-Bound Contextual Judgment

Every creative Graph checkpoint co-loads
`skills/idol-contextual-creative-judgment/SKILL.md`. The checkpoint selects one
profile from `automation/graph-creative-judgment-registry.yaml`; the exact
profile, its value hash, artifact schema, and validator are projected into the
Role Context Pack. This is stage-local context, not another broad instruction
closure.

The assigned model or human authors one 0--4 result and complete prose evidence
per applicable criterion: locator, observable claim, screen consequence,
preserve, change, do-not-infer, correction action, and acceptance evidence.
Scripts validate profile identity, range, source hashes, hard gates, and the
next graph edge only. Scores are never averaged. All applicable criteria must
be at least 3 and the profile's critical criteria must be 4 before
`director_review`; the Director still judges exact bytes independently. A
non-Founder output cannot promote from a prose field alone: its output node
must `judged_by` one hash-bound contextual-judgment node, that node must
`selects_next` the assigned Director review, and only that review may promote
the exact output bytes.

PRE-FP alone scores and locks target/audience/message/storyline. Reference
collection grades candidate function and transfer evidence before selection.
Front Planning, the existing `fp_hero_core` Draft Keyframe Proof, 02B pixels,
03V playback, and 04 edit playback use separate profiles. Downstream stages
check lock violation or visible realization instead of rescoring the PRE-FP
decision.

Each judgment binds an immutable content-addressed profile release under
`automation/graph-creative-judgment-profile-releases/`, including its file
SHA-256 and profile-value SHA-256. The registry's current pointer chooses a
release only for a newly admitted judgment; an older Role Context Pack or
judgment remains pinned to its original release. Never edit a release in place
or reinterpret historical outputs against a newer profile.

Each current release pointer also binds a promotion artifact. Only the exact
registered seven-release bootstrap set may use an execution-disabled shadow
seed. Any later current-pointer change requires the exact old/new release pair,
proposal-to-shadow-to-pilot predecessor hashes, and a Founder-authored approval
receipt. Validation cannot tune a criterion, move a pointer, open execution, or
authorize the Graph default switch.

The shadow control path is:

```text
native Goal admission
-> exact-node Role Context Pack + immutable judgment profile release
-> assigned model/human authors output and 0--4 prose judgment
-> Director exact-byte review
   -> accept: promotion closure and next legal node
   -> patch/reject/hold: same-owner bounded correction attempt + fresh Goal
-> Founder stop only at G0--G4 or exact paid/external/destructive/release authority
```

`scripts/idol_graph_run_controller.rb` currently calculates only the next
decision in that loop from hash-bound state. It emits one of
`dispatch_or_resume_model`, `await_director_review`,
`route_bounded_correction`, `await_founder_decision`, or `hold`, plus a
same-stage/disjoint-cohort frontier set only after every current head is covered
by an exact path/SHA-256 `canonical_head_join_dependency`, a non-persisted
append-only event intent, and an idempotency key. A multi-head set is not
execution authority. Creative-stage and paid/download/capture/upload/external/
destructive/release requirements are unioned rather than allowed to mask one
another; until the typed DDI producer and receipt reducer exist, every such
material requirement remains shadow-missing and execution stays false.
It performs
no provider launch/resume, Goal creation, ledger write, score authorship,
Director review, creative PASS, or promotion. Therefore the repository is
still `shadow_not_default`: autonomous provider execution, an event writer,
real-song pilot evidence, and the exact Founder default-switch receipt remain
separate cutover work.

Judgment criteria evolve only through the evidence-backed maintenance loop in
[`harness-improvement-review-loop.md`](harness-improvement-review-loop.md).
Directors may propose better observable evidence or correction prompts, but
scripts never tune scores. Floors, critical-4 and not-applicable rules, Founder
gates, and authority boundaries require Founder approval. No release may add a
total, average, weight, or percentage score.

plus audio animatic, G3 reviewed section playback, and G4 final master/release.

mutation/upload, and public release. A worker, script, board, or derived pack
cannot imply approval. Official/original source eligibility, restricted-edit
permissions, media security, and smallest-owner rules live in the activated
policies.
