# Workbench, Runtime UI, Queue, And Handoff Maintenance

## Activation

Load this module for the Workbench, runtime UI, Director Dispatch Index,
pointer-only context, queue/lease behavior, event waits, rollover, handoff, or
review-surface maintenance. It does not authorize a new task, provider, or
external mutation.

## Pointer-Only Surfaces

The Director Dispatch Index, scoped views, aggregate manifests, and review HTML
are read models. They carry task/session lineage, scope, state, input/result
digests, output pointers, review disposition, board links, holds, and next
actions. They do not embed images, raw pools, full transcripts, long prose, or
creative truth. Each read model has one mechanical writer; a source-set digest
is rechecked before replacement so a concurrent edit aborts instead of merging
silently.

Director Boot Packs contain only active stage/checkpoint, explicit locks,
canonical heads, open/held tasks, board cycle, and next actions. Full chat,
unrelated sections, rejected dumps, historical prompt prose, maintenance
examples, and un-intaken files stay out of creative context.

One cumulative Workbench keeps stable creative node ids while G-30 through
G-60 add routes, Major/Sequence/Core comparisons, exact production scope,
actual Cut outputs, Motion Storyboards/playback, and edit. Actual visuals and
unresolved creative impact lead the view; transport closure is a folded summary
unless blocked. A stage change does not create a second HTML truth or renumber
the same node.

Execution consumers use the exact completed native turn text bound to the current
run, session, agent and turn. Terminal previews may be shortened for display;
startup admission, controller control blocks and Department returns must never
parse those shortened previews. Release transient full text after its single
execution handoff or terminal failure; keep it outside persisted UI/context
summaries. A missing, failed, mismatched or capacity-exceeded original holds.
An explicit retry needs native-source recovery and current authorization; a
saved preview or partial return cannot substitute. Run changes discard transient
text. A handoff is not the Director's acceptance of the work.

## Queue And Wake Rules

Returns to one Director enter one deterministic single-flight queue. The
Director closes the earlier exact-byte read, requirement judgment, and
acceptance/HOLD before opening the next. Canonical promotion uses one global
Overall lease. A worker wakes its declared recipient only for `final`, `hold`,
`authority_request`, or `milestone`; the compact payload contains exact output
or aggregate-manifest pointers, hold/rejection, material risk, unresolved
decision, and hashes—never raw commentary.

Capacity is a ceiling, not a quota. New work waits behind review backpressure,
writer backlog, owner/path collision, provider limits, or Founder locks. A
maintenance task cannot use spare capacity to launch a creative grandchild.
Company Ops may schedule at most 15 Company-managed physical Grok sessions.
IDOL separately limits physical nonroot Grok workers to 8 and Cursor workers
to 6 (combined14); these are not provider-native helper count or depth limits.
The bridge does not synchronize runtime occupancy across those pools. Company
cannot overwrite IDOL per-lane writer, director, media, or backpressure caps. A lost wake resumes from the durable claim or admission;
duplicate claim or duplicate promotion is a HOLD. Raw Markdown, YAML, or
judgment evidence is not a wake and is not executable.

## Workbench Rollover And Handoff

Stable logical lineage and physical session identity are separate from an
immutable dispatch attempt. A correction creates a new attempt in the same
room and preserves prior evidence. Keep the legacy CDD rollover and Graph
same-lane successor routes separate:

- A legacy-pinned CDD rollover uses the historical router and still requires a
  hash-equal safe checkpoint, released owner lease, complete pointer
  restoration, its registered successor route, and the legacy explicit Founder
  confirmation receipt. It never writes Graph router state.
- A Graph-v2 same-`lane_id + macro_stage_id` successor requires the safe
  checkpoint and successor pack, one released writer lease, an exact registered
  provider binding, a persisted typed provider Goal terminal-event pointer, and
  the lane-local single-writer CAS. The Graph Goal evidence contract verifies
  the exact event bytes and provider correlation before admission; the state
  re-verifies them on later reads. This operational succession requires no
  separate Founder confirmation and creates no new Founder gate.

Missing or stale evidence is a HOLD and leaves the primary as the only writer.
Founder interaction remains at G0--G4 and at the existing paid, external,
destructive, release, explicit-lock, or other named authority gates. A Grok
handoff is optional transport, not a second authority.

External Grok execution, Drive mutation, paid generation, upload, publication,
and protected-output disposal require their separate Founder authorization.
The maintenance profile can validate and return pointer-only runtime state but
cannot perform those actions or promote creative truth.

## Runtime Review

The recipient Director independently reads the exact returned bytes and the
governing profile/schema/module sources. Mechanical UI or lifecycle checks do
not judge creative quality, identity, safety, pixel, or playback adequacy. A
missing pointer, stale digest, owner collision, or incomplete successor pack
is a HOLD with the exact repair owner and affected scope.
