# Script, Validator, And Registry Maintenance

## Activation

Load this module for a reusable script, validator, extractor, worklist/state
report, export/preflight helper, or the script authority rows in a surface
registry. Run-specific helpers remain under their owning run unless the
assignment explicitly authorizes promotion.

## Allowed Script Roles

Top-level scripts are shared execution aids only when they validate contracts,
measure evidence, build pointer-only worklists, report state, or export a
validated artifact. A deterministic compiler may serialize already-approved,
source-hashed fields into a fixed compatibility shape, expose the mapping, and
fail closed on missing/stale truth. It may not choose or strengthen action,
camera, composition, choreography, wardrobe, world, song meaning, prompt
intent, or Founder review.

Repair and migration helpers may reshape existing bytes or write diagnostic
candidates under `work/`; they never fill creative fields from counts, labels,
placeholders, or templates, mark prose as model-authored, or write canonical
stage truth. A run-specific hard-coded helper is non-reusable until its owner
documents or refactors it.

Before creating a command, use `scripts/README.md` as Start Here, then inspect
the machine registry in `automation/idol-script-registry.yaml`, its schema and
checker, the complete searchable `scripts/INDEX.md`, and the affected role
guide. Prefer extending a validator or extractor over adding a duplicate. Do
not copy a long command catalog into a skill, profile, or wiki module. Ordinary
creative workers do not load the full INDEX or machine registry; this full
discovery set belongs to the maintenance checkpoint only.

## Validator Contract

Each validator names its input paths, schema/contract version, exact output
shape, and failure behavior. It may check path, hash, lifecycle ordering,
version, scope, ownership, and declared coverage. It must not claim pixel,
playback, semantic, or creative adequacy. A `pass` from a structural validator
is not a Founder PASS.

Tests should exercise both a valid hash-bound fixture and the smallest invalid
mutation for each protected invariant. Keep fixtures noncanonical and free of
past-run scene nouns, ready-to-copy prompts, or secrets. When a profile or
module changes, update the directly owning tests in the same patch and report
the exact command and result.

Provider routing validation resolves logical aliases through
`automation/harness-provider-profile-registry.yaml`, then verifies the exact
provider-source hash, model/effort capability snapshot, run selection, no-
fallback rule, active Director singleton, and return recipient. It must not
duplicate Codex or Grok model literals in a second authority table.
`scripts/validate_company_ops_idol_bridge.rb` fail-closes Company Ops ingress:
no execution before Dispatch + Goal + Pack, no self-review or self-promotion,
no grandchild creation, three-submission ceiling, separate IDOL helper-8 and
Company Ops session-15 caps, non-executable raw Markdown/YAML/judgment
evidence, no Cursor Cloud live POST, no Graph v2 default switch without a
verified receipt, and no duplicate claim or promotion after restart. The stage
validator separately keeps stable transport stage ids while testing current
01 Core, 02A Branch, CDD-through-03V, and Edit Director ownership.

When a schema changes, close its producer and every reachable consumer or
validator in the same migration. A compatibility reader is tested against a
frozen legacy fixture and excluded from new authoring. A previously active
script that is now historical stays fail-closed; do not make it look current
merely to satisfy registry reachability.

## Script Surface Registry

When a reusable script contains both a canonical creative filename and a write
operation, its surface-version row must declare a non-creative authority or a
reviewed noncanonical exception naming what it writes. An unclassified lexical
match is a HOLD. This guard supplements, rather than replaces, review of
dynamic paths and run-owned helpers.

Mechanical output may include exact source paths, JSON pointers, SHA-256
digests, and receipts. It must not copy raw commentary into a wake event,
rewrite another owner, or infer approval from a successful command.

Refresh `automation/idol-script-registry.yaml`, `scripts/INDEX.md`, the owning
contract-version entry, and every tracked surface revision/SHA only after the
final implementation bytes are stable. Registry refresh is one mechanical
closeout step, not evidence that a creative or playback gate passed.
