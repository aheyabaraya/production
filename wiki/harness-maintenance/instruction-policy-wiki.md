# Instruction, Policy, And Wiki Surface Maintenance

## Activation

Load this module for a change to `AGENTS.md`, a file under `policies/`, an
active wiki router/specialist page, a conditional-reference index, or the
frozen maintenance-history boundary. It does not replace the changed file or
the applicable policy; read those exact sources to EOF as well.

## Canonical Placement

Use this placement order:

1. `AGENTS.md` for always-on authority, role distinctions, and protected
   invariants.
2. `policies/` for task-activated canonical rules directly governed by
   `AGENTS.md`.
3. `wiki/production-system.md` for the compact graph-engineering shape, stage map, and
   read discipline.
4. Specialist `wiki/` pages for one bounded production or maintenance detail.
5. `skills/**/SKILL.md` for procedural execution truth.
6. `handoff/grok/` only for Grok-specific tooling and temporary transport.

Shared rules do not belong in `handoff/grok/`. Artifact location, output
ownership, mirrors, handoff, and cleanup remain in
`wiki/artifact-management-system.md`; do not repeat those rules here.

## Transaction For Prose Changes

Before adding prose, search `AGENTS.md`, `policies/`, and `wiki/`; identify the
strongest canonical owner and the exact activation token. Keep the compact
router readable and move only conditional detail whose trigger is explicit.
Every moved rule needs a stable heading, one link from its router, and an
unambiguous reason it is not loaded by unrelated checkpoints.

Preserve natural creative language and observable/audible execution facts by
linking to `AGENTS.md` and `policies/creative-production-constitution.md`.
This maintenance module may describe where those rules live, but it must not
rewrite lyric, prompt, camera, action, choreography, or Founder-review truth.

For a chain-wide semantic migration, update the protected invariant and its
exact detail owner together. Replace old stage/gate/owner terms in the
instruction policy instead of retaining them as required compatibility
literals. Stable transport ids may remain when explicitly documented as ids,
not current creative labels; legacy terms otherwise belong only in a pinned
reader or frozen evidence surface. Run the instruction audit against the final
bytes before registry hashes are refreshed.

## Bias-Safe Examples

Removing past-run bias does not mean deleting every teaching example. Keep a
noncanonical pattern in the form:

```text
current input / need -> current evidence -> compared routes
-> selected observable owner field
```

The pattern must stop before ready-to-copy creative truth. Exclude past-run
names, distinctive scene nouns, full prompts, and copy-ready action, camera, or
motion. Examples stay outside runtime context and generation; current
evidence, not the example, determines the result.

## Conditional Routing And Size

Use the active `automation/instruction-surface-policy.yaml` as the numeric
source for targets, reviewed ceilings, protected terms, required headings, and
frozen-history behavior. Do not maintain a second threshold table in prose.
When a long conditional reference is necessary, provide an index or stable
headings and an activation rule. Size warnings are diagnostics. A split,
merge, compression, or deletion requires explicit Founder authority in the
current request; a target or ceiling warning never grants that authority.
Automatic remediation is false unless that current request explicitly grants
the authority; preserve the file when it does not.

After structural instruction changes, run:

```text
python3 scripts/idol_instruction_surface_audit.py
```

Inspect the report for missing links, protected invariants, forbidden history
patterns, stale paths, and conditional references. The report is a mechanical
check, not creative approval.

For the PRE-00 through 03V convergence, the protected current vocabulary is
`FP-A/B/C`, `MJxx`, one-second exact-five Sequence Units, 01-owned Official
Core, 02A-owned Branch, cumulative `G-30` through `G-60`, and provider-neutral
one-Cut/one-image packets. Historical F-gates, Major `Mxx`, Branch-only media
labels, and legacy Grok tool names may appear only inside an explicit
legacy/evidence classification.

## History Boundary

Routine history belongs in Git. Do not append a dated narrative or create
per-change, monthly, or version-suffixed files. The frozen
`wiki/harness-maintenance-history.md` snapshot is pointer-only compatibility
evidence and is excluded from normal startup and creative checkpoint loads.
