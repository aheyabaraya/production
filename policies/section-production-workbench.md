## Unified Founder Workbench Review

The active `idol-html-review-board.v12` shell serves every visual review stage.
Each run has one stable active HTML projection, ordinarily
`RUN/review/founder-workbench.html`. Front Planning, member styling, G-30
route/Stack/Sequence/Core-reference/Hero comparison, G-40 01 Core plus 02A
Branch authorization, G-50 actual Cut results, 03V Motion Storyboard and
480p/720p playback, and G-60 edit review extend that same source-bound board as
ordered review cycles. A stage change does not create another member, styling,
core-cut, or playback HTML board. Superseded cycles stay collapsed/read-only;
the named active cycle alone accepts decisions.

New work uses stable cycles `g00_direction_draft`, `g10_song_lock`,
`g20_visual_identity_lock`, `g30_fp_final`, `g30_experiment_disposition`,
`g40_core_branch_authorization`, `g50_branch_results`,
`video_playback_internal`, `g60_playback_edit`, and `g70_release`. Legacy
`discovery`, `direction_synthesis`, and `fp_final` ids are read-only display
aliases and cannot be newly written. `g30_fp_final` presents exactly FP-A/B/C,
the CDD recommendation, ordered Major Stacks, 2--4 Sequence compositions and
Core candidates, every selected Core reference or Founder waiver, and actual
Hero proof. New G-30 cycles place Sequence sheets as Major parents on
top, grouping each event sheet with its one or two Core marks, so the Founder
sees the flow and those cut images together. A section may show many Majors. A still gallery
does not replace Major. Sequence Units display as one five-frame sheet or one
chronological row per unit, not a loose frame dump. Core is a mark on the
selected flow or a better still of the same moment, never a start / middle /
end dump of one Sequence counted as extra Cores.
Existing COLOR STAY creative boards are not redrawn by this layout until an
exact Founder sentence asks to reproject that run. Reference completeness,
Hero generation, and a CDD `consecutive_same_flow` hold are separate badges;
any of those missing or open disables `select_candidate`. `g40_core_branch_authorization` binds the
exact derivative/production scope and Cut set but does not grant paid execution.
`g50_branch_results` judges actual output pixels. `video_playback_internal` is a
CDD checkpoint, not a second Founder gate.

The Founder-visible CDD task develops and reviews the development Workbench
through actual image, Motion Storyboard, and playback. Overall is the only
Founder-conversation owner, preserves the verbatim decision receipt, inspects
CDD-reviewed surviving media, owns the recommendation and canonical promotion,
and retains final acceptance. Raw worker pools never enter the board.

After 03V handoffs, the fresh Founder-visible Edit Director task owns the 04
Workbench and merge. Edit shard cards return only to Edit Director;
Edit Director reviews and merges them, then returns one passed 04/05 package to
Overall without gaining promotion authority.

Its fixed reading order is:

1. target and message;
2. whole-video and section flow;
3. section;
4. core cut;
5. branch cut.

Every card declares the exact affected section, core cut, branch cut, and
revision scope it owns and shows the necessary source or output pixels/playback.
Discovery cards use only discovery actions. Canonical stage-gate cards use only
PASS, HOLD, or REJECT; no Discovery signal silently promotes creative truth.

The managed visual profile keeps member face and styling evidence in an
adaptive left block with a practical minimum around `280px` and a bounded
proportional width, while character/scene/sequence references expand in a fluid
right row. Primary face and style compare side by side when space permits;
additional styling stays in one compact horizontal strip. At the existing
responsive breakpoint, the complete member block stacks full-width above the
references. 02A Branch-Cut children append below the parent Core-Cut row. This
is a review layout only, not a separate face-reference transport lane and not a
frontal-face requirement. Object/world cards render an explicit no-member
state. All media receive deterministic `01 / N` presentation indexing. All
reference/styling pixels use `object-fit: contain`; the right row shows up to
four equal desktop slots and, on overflow, stays one row with left/right,
touch, and trackpad horizontal sliding plus a visible range indicator. Mobile
shows one slot. Thumbnail click opens the full image; a second click on the
enlarged image, overlay or close-control click, and Escape all close it.

The stable review projection owns one pointer-only asset register. Every item
exact-copies its canonical path/SHA, original owner, first-seen and latest
binding revisions, typed source stage, target, lane role, declared order,
lane-owned state, supersession relation, and explaining receipt. `NEW SINCE
LAST REVIEW` remains visible until the owning lane assigns a target and state.
Reusing the same bytes adds a binding rather than a copied asset. Held,
rejected, superseded, and older-cycle media remain findable in collapsed
count-bearing groups and load only when opened.

Workbench and HTML review surfaces consume the same manifest hash, board
revision, active cycle, asset groups, and order. Any mismatch is a visible
stale-review HOLD. In the 02A Final Planning cycle, the internal FP Close
storyline is a read-only exact lineage and the eligible 02A cards are the
decision-bearing scope. No second Founder PASS is requested for FP Close. A
non-closed or stale FP source, incomplete 01 expansion, or ineligible 02A target
holds the affected final-planning card instead of presenting it as approved
truth.

01, 02A, 02B, generated-review, 03V, and 04 owners project read-only status and
canonical media pointers into that board. The Workbench gains no downstream
stage-writing authority and never copies a generated original for display.

Every eligible owner feed is registered once at
`RUN/work/review-projection-owner-index.yaml`. That index is a hash-bound list
of existing owners and pointer adapters, not a media register or creative
owner. On managed open or refresh, the Workbench deterministically compiles it
into `RUN/work/review-projection-source-set.yaml`, requires the declared adapter
kinds to exact-cover the registered rows, and holds on a missing, stale, or
multiply owned input. Do not hand-maintain the derived source set or its
`new_since_last_review` state. The resulting pending index is copied into
`automation/current-next.yaml` only when that pointer already names the same
run; projection never changes the selected run, creates a task, or infers an
approval.

During a member identity-card cycle, the same workbench shows the approved face
and selected styling component sources as separate evidence beside the clean
three-panel candidate. The clean card itself contains no source strips, labels,
or comparison chrome. The surrounding comparison view remains review evidence
after the clean passed card is promoted.

Before 02A, a hand-authored `CCxx_slug` is a stable board anchor only. 02A still
owns official `core_cut_id` and `branch_cut_id` values. When those values
arrive, bind them under the existing visible parent without renaming deep links
or copying the card to a second board.

The shell owns its sans and mono font tokens, colors, spacing, sticky offsets,
breakpoints, print rules, and lightbox. Run HTML may supply content but may not
fork those presentation rules. The renderer embeds the managed CSS/JS and
records their SHA-256 values so a layout or font change is auditable.

### Founder Projection Kinds

Ordinary Founder gates after startup use three named projections on this same
board, never a sibling HTML page:

- `direction_alignment` — G1. Existing `g30_fp_final` remains the board
  surface. Founder sees one Overall-recommended whole flow, section jobs,
  visual-regime change, and where the 2--3 second transition tendency
  accelerates or eases. Founder does not see raw search results, every URL,
  worker reasoning, near-duplicates, or CDD 0--2 candidates.
- `draft_keyframe` — G2. After 02A Draft Keyframe Proof and before final 02B
  execution. Founder sees every active section's keyframe contact sheet, the
  image-only hard-cut animatic on selected audio, one motion-intention line per
  section, CDD pixel review, Overall whole-video recommendation, material risk,
  and one nearest alternative. Founder action is section/card `PASS`, `HOLD`,
  or `REJECT`; exact card correction; or a whole-route or upstream-lock change.
  G2 PASS authorizes only the named section/Cut set, provider, attachment
  group, output count, and budget for final 02B. Scope outside that envelope
  is a separate authority request. Draft pixels are not Production Cuts and
  are not 03V sources.
- `section_playback` — G3. After the cohort CDD, Overall, or Edit Director has
  closed actual playback review. Founder sees that section's actual
  selected-audio playback, optional 0.5s or 1s QC sheet, incoming and outgoing
  handles, the Director recommendation, and remaining material risk. Founder
  does not inspect the raw reference loop or each I2V clip. HOLD returns to
  the smallest owner.

G4 remains `g70_release` plus the existing final-master, protected-output, and
public-release gates.

Until renderer, export/intake schemas, and owner-index adapters admit dedicated
cycle ids, these projections occupy the same `RUN/review/founder-workbench.html`
path as named `projection_kind` values. Do not invent a second board. A
renderer or schema that cannot yet project `draft_keyframe` or
`section_playback` is a producer/consumer HOLD for that gate, not permission to
ask Founder to inspect raw pools instead.

When a G2 envelope is bound, `g50_branch_results` is the CDD-owned generated
pixel cycle for in-envelope cards. Founder sees only material-drift or
envelope-exception cards there. `video_playback_internal` remains the CDD 03V
checkpoint. `g60_playback_edit` remains the edit surface; G3
`section_playback` is the Founder-facing reviewed section preview and must not
reopen every clip as a second Founder loop.

### URL And Pool Collapse

Director and Founder context collapse URLs by default. Cards show source id,
selected local pointer/hash, one-line observed evidence, one-line
source-to-screen delta, preserve/discard, why the survivor beats the nearest
alternative, and the CDD disposition. Raw URL lists, search-query history,
full source-analysis prose, worker transcripts, and rejected pools stay
collapsed. Expand a source-intake manifest only for recapture, eligibility
audit, or provenance dispute.

A whole contact sheet counts as zero. Sequence Units display as one five-frame
sheet or chronological row. Motion evidence must remain a contiguous event
pointer, not a URL gallery.

### Draft Keyframe And Section Playback Cards

A `draft_keyframe` card names the exact section, Major/Core, draft-pixel
pointers and hashes, selected-audio animatic pointer, motion-intention line,
CDD 0--4 vector with locators, Overall recommendation, and the 02B execution
envelope it would authorize. It never carries a raw reference pool.

A `section_playback` card names the exact section, incoming/outgoing handles,
actual playback pointer and hash, optional QC sheet, CDD/Overall or Edit
Director recommendation, remaining material risk, and the smallest-owner
return if HOLD. It never asks Founder to re-judge each I2V clip.

Section-Cluster CDDs project only their assigned cohort. Overall projects
cross-cohort boundary, repetition, and whole-film integration. Edit Director
projects 04 merge cards. No CDD writes another cohort's cards.
