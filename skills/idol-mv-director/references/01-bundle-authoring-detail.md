# Active 01 Bundle Authoring Detail

This reference applies only to active 01 `3.0`. There is no separate active 01A
or 02 creative artifact.

## Input Projection

01 must exact-project:

- Front Planning source path and SHA-256;
- the complete PRE-00-rooted full-storyline lineage, including immutable
  original, active full text, every revision, contextual density review, and
  reference-function receipts;
- target/message and whole-video spine;
- section order, timing, member allocation, and choreography policy;
- director-quality-passed Major Scene ids and Key Screen Anchor ids from the
  consolidated Founder-passed FP bundle;
- current-title asset package and section assignments;
- selected reference interpretation ids, paths, hashes, and directness;
- 00A/song source;
- every Official Core id, exact governing reference or Founder-authored
  named waiver, and exactly one passed primary image path/SHA per Core.

Read the full-storyline projection before target/message summaries or section
detail. `whole_film_spine` is an index only. If any projected value changes,
return to Front Planning.

Every assigned Key Screen Anchor must be expanded by one or more 01 scene or
coverage records while preserving its id, visible action/hold, still-camera
geometry, composition, reference-function bindings, and passed current-title
visual inputs. One 01 record may consume multiple compatible anchors, but no
reviewed anchor may disappear or be replaced by a portrait-first default.

## Section Expansion Record

Each section record should make the following production answers obvious:

### Dramatic Job

What does this section contribute that the previous one did not? It may seed,
embody, complicate, contradict, release, resolve, echo, build relation, reveal
world, create tension, perform, transition, withhold, or leave afterimage.

### Observable Screen Event

State:

- where;
- who or what is visible;
- what they do or intentionally hold;
- what object/environment changes;
- what relation or tension is legible;
- what exact audio cue activates it.

### Staging

State body/object position, facing, distance, contact, occlusion, entry/exit,
and gaze only where visible.

### Still Camera

State height, distance, direction/angle, depth, placement, crop, negative space,
and lighting/material balance. State why this view makes the section readable.

### Directorial Branching Opportunities

For each major event, record an open set of materially different screen
realizations that 02A can select or refine. Each opportunity states:

- how it remains part of the same governing event;
- what new observable screen information it contributes;
- whether it is direct message or empathy evidence, or which necessary setup,
  complication, reaction, result, intentional withholding, relation, world,
  performance, or bridge job makes later evidence legible;
- the action, reaction, space/object consequence, insert, or other visible job;
- the applicable still-camera coverage ids;
- its continuity or edit use;
- what neighboring branch it must not merely repeat.

Do not enforce a category quota. Do not use start/end labels as a substitute
for a distinct screen contribution. The same action with only a lens, angle,
shot-size, or beauty change is not a new opportunity unless the changed view
adds viewer knowledge or performs a necessary continuity job. If the governing
event changes, 01 authors a new Official Core; it is never deferred to 02A as a
Core-boundary implication.

### Reference Application

For each selected application:

- interpretation id;
- source and derivative path/hash;
- directness;
- preserved action/staging/camera/crop/sequence facts;
- current-member/song substitutions;
- discarded source facts;
- continuity risk.

### Current-Title Visuals

Project the exact member visual only for meaningful member visibility. Bind
governing scene/sequence references and any supporting component references in
the canonical combined order; do not create or imply a separate downstream
background/world package. Current-title member visuals are newly created and
Founder-reviewed for the current album/title before becoming title defaults; a
previous album package is not a substitute. The member visual does not choose
pose or camera.

### Choreography

For `primary`/`supporting`, bind source path/hash, segment, ordered body states,
and timing readability. Otherwise preserve the non-dance policy.

### Transition

State what the entering frame inherits and what the exit leaves for the next
section. This is whole-video continuity, not permission for a 02B worker to load
another section.

## Sharding

Author one physical section shard at a time. Each shard:

- has one owner;
- contains one section;
- binds the same Front Planning/00A source hashes;
- owns disjoint output paths;
- validates independently;
- does not load another section's detailed cuts or prompts.

The continuous director and coordinator retain the whole-video spine and perform
ordered merge/reconciliation.

## Review

Review section direction for:

- distinct content job;
- target/message consequence;
- reference fidelity;
- title identity;
- exact Key Screen Anchor coverage and preserved reference-function
  combinations;
- observable action;
- still-camera specificity, contextual progression, and intentional use of
  recurrence or variation;
- choreography source integrity;
- transition continuity;
- feasibility and generation clarity.

Machine checks cannot decide these creative judgments.

## 02A Handoff

02A exact-imports every 01 Official Core byte unchanged and determines only:

- Branch coverage beneath the imported Core;
- 1..N ordered Branch Cuts per Core;
- per-branch still view and selected visual inputs;
- expected output ownership.

Any requested Core event boundary, meaning, governing reference/waiver, still
camera, or passed-primary-image change returns to 01. 02A never rewrites those
fields in place.

If 02A must invent the section action, space, still camera, reference
application, branching logic, or title package, 01 is not ready.
