# IDOL Planning CDD

Use this skill only after a verified Graph v2 switch, for exactly one
`frontier_director` lane inside the pre-G-40 Planning CDD Cell. Until that
switch, the legacy-pinned route keeps exactly one durable Founder-visible
compatibility CDD as `AGENTS.md` states; do not instantiate this lane. It
authors one lane-owned Decision Set. It does not consume the integrated Front
Planning artifact, promote canonical truth, or continue into 02B/03V.

The three allowed modes are:

- `story_audience_lead` (`CDD-P1`);
- `visual_reference_development` (`CDD-P2`);
- `section_kinetic_architecture` (`CDD-P3-Ci`, one per roster-derived cohort).

Read only the matching mode reference before authoring:

- P1: [references/story-audience-lead.md](references/story-audience-lead.md)
- P2: [references/visual-reference-development.md](references/visual-reference-development.md)
- P3: [references/section-kinetic-architecture.md](references/section-kinetic-architecture.md)

Overall remains the sole Founder-conversation, whole-film promotion, and final
creative-acceptance owner. P1 alone uses `idol-front-planning-director` after
Founder G2 to exact-link reviewed Decision Sets and produce the G-40 read-only
handoff. Planning workers return
to their assigned CDD lane; they do not become CDDs or write another lane's
Decision Set.

## Admission

Require:

- a verified Graph v2 switch receipt; until that receipt exists, HOLD and do
  not instantiate a Planning CDD lane, extra physical CDD, or stage;
- exact run, Founder epoch, active storyline/audio heads, and planning
  checkpoint;
- one `planning_cdd_mode` and its unique graph lane id;
- exact writable Decision Set paths and read-only cross-lane inputs;
- a `frontier_director` provider receipt with no fallback;
- Department Dispatch, native Goal, Role Context Pack, input digest, output
  manifest, return recipient, and stop conditions;
- physical generation `primary` or `successor`, never a third lane session;
- proof that no other active owner writes the same planning fields.

P3 additionally requires selected audio, a provisional section boundary map,
and one exact `planning_section_cohort_id` covering 2--3 contiguous sections,
except one explicit singleton when the whole title has only one section. Do
not launch P3 early to fill capacity. Hold on missing, stale, overlapping, or
multiply owned inputs.

## Shared Workflow

1. Restate the named planning gap and observable screen consequence.
2. Dispatch only disjoint `research_medium` or `worker_high` packages needed to
   close it. Provider capacity is a ceiling; lane backpressure stops launches.
3. Review exact evidence, not worker self-scores or schema presence.
4. Author one lane-owned Decision Set with preserved truth, changed truth,
   evidence pointers, alternatives, risks, invalidations, and next legal action.
5. Grade applicable criteria on the 0--4 Director scale in
   `policies/section-production-front-planning.md`. Scripts may not invent a
   grade. An average, total, or schema PASS is not admission.
6. P2 and every P3-Ci return the reviewed Decision Set only to P1 through the
   exact-link route. P1 alone returns the integrated Planning Cell milestone to
   Overall. A cross-lane conflict travels inside the P1-bound Decision Set as a
   compact conflict capsule; it is not a second P3-to-Overall return route.

P1 is the only planning integration writer. It exact-links P2/P3-Ci reviewed
Decision Sets and may add connective planning prose in its own scope. It may
not silently paraphrase, erase, or reverse their decisions. A material conflict
becomes a compact conflict capsule for Overall.

## Disjoint Decision Sets

Write only the fields named by the active mode. P1, P2, and each P3-Ci never
co-author the same planning field.

| mode | unique write scope | must not write |
|---|---|---|
| P1 | PRE-FP lock projection, storyline descendants, message progression, song/screen reward, route recommendation, exact-link integration | visual/reference dispositions, section/Major/Sequence/Core topology, still-camera authorship, kinetic structure |
| P2 | source eligibility, four-role reference dispositions, identity/world/look/composition evidence, motion-evidence coverage, transfer boundaries | storyline original/descendants, section roster topology, G-40 handoff prose |
| P3-Ci | that cohort's section jobs, Major/Sequence/Core marks, still camera/composition, 2--3 second kinetic tendency, motion readiness, Draft Keyframe Proof requirements | another cohort's sections, P2 source dispositions, P1 storyline root, 02B pixels, 03V temporal motion |

## Contextual 0--4 Grades

Co-load `idol-contextual-creative-judgment` and apply only the exact
`judgment_profile_id` in the Role Context Pack. In Graph v2, the common prose
judgment is the only newly authored score artifact. It records observable
consequence, preserve/change/do-not-infer, correction, acceptance evidence, and
the next legal edge. The older planning vector remains parse-only legacy-pinned
evidence and must not be co-authored for the same Graph judgment.

Assigned Directors grade actual media and named context. Meanings:

| grade | meaning | allowed state |
|---:|---|---|
| 4 | can govern the main judgment; actual screen evidence is sufficient | promotion eligibility only |
| 3 | strong, but needs combination or a small correction | internal combine/correct |
| 2 | valid comparison evidence, too weak as a production input | held evidence only |
| 1 | low value in the current work | reject |
| 0 | collides with a PRE-FP lock, source, identity, or execution condition | hard reject/hold |

Promoted items require grade 3 or higher on every required criterion named by
the checkpoint and grade 4 on both motion and still-camera/composition for every
material Major. Record stage-appropriate criteria in
`idol_graph_contextual_judgment.v2`; never reuse a planning profile as the
generated Production-Cut pixel or playback profile. A grade is not
automatic PASS. Local, Pairwise, and Overall Global review of exact bytes remain
mandatory. Optional criteria stay `not_applicable` with a reason; do not invent
dummy references to fill them. Performance readability is graded only when
`performance_mode` is `supporting` or `primary`. Target empathy and message are
PRE-FP locks, not repeated downstream scores.

## Graph Contract

Emit typed node and edge evidence rather than a second creative artifact:

- node identity, mode, owner, provider session, Goal, checkpoint, and state;
- `owns`, `dispatches`, `returns_to`, `reviews`, `derives_from`, `supports`,
  `contrasts`, `transforms`, `invalidates`, and `requires` edges as applicable;
- exact input/result digests and output hashes;
- `proposed`, `running`, `returned`, `reviewed`, `promoted`, `hold`,
  `invalidated`, or `retired` state.

Scripts may validate this topology and provenance. They may not invent a story,
reference function, screen consequence, grade, conflict resolution, Founder
lock, or creative PASS.

## Succession And Retirement

Each logical lane permits one physical primary and one successor per stage.
Use a compact successor pack and lane-local single-writer CAS. If the successor
cannot close the checkpoint, narrow unowned worker scope or return HOLD; never
spawn a third Planning CDD session automatically.

After Founder G2, P1 alone exact-links the reviewed P2/P3-Ci Decision Sets and
emits one hash-bound G-40 Planning Cell handoff. P1/P2/P3-Ci then become
read-only rollback points. They do not write 02B pixels or 03V motion. Each
post-G-40 Section-Cluster CDD exact-carries the same `section_cohort_id` into
its disjoint 2--3-section cohort.

## Return

Return a compact lane manifest containing:

- lane/mode, checkpoint, physical generation, provider receipt, and state;
- reviewed Decision Set pointers and hashes;
- 0--4 grades with evidence locators, N/A reasons, and no aggregate score;
- evidence and actual media locators needed to inspect the decision;
- cross-lane dependencies, conflicts, holds, and invalidated descendants;
- integration status, recipient, and next legal action.

For P2/P3-Ci the recipient is always `planning_cdd_p1` through
`planning_cdd_p1_exact_link`. Only P1 may name Overall as the Planning Cell
return recipient after exact-link integration.

Exclude raw candidate pools, full URL lists, worker transcripts, superseded
prose, and unrelated lanes. A structural PASS is never creative PASS.
