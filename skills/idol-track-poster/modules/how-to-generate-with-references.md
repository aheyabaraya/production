# Generate Track Posters From Actual References

Every track poster starts from the current title's bound actual references. The
first semantic owner must inspect their pixels and write an
`interpretation_receipt`; later poster work consumes that receipt without
inventing a new meaning. The original image remains provenance and any
separately approved generation attachment.

## Local Authoring Read

The assigned current-title identity/track-poster author under CDD authors a new
or meaning-changing prompt. One explicitly authorized bounded forensic adviser
may inspect one named actual-pixel or returned-image risk and return only
observable facts, locked-rubric compliance, technical defects, uncertainty, and
a reversible technical pass/hold/rerun to the assigned author and CDD. The
adviser never writes a prompt delta or batch, selects among creatively valid
candidates, or fills/reinterprets missing creative truth. Before authoring,
open:

1. the member character board for local face/body proportion judgment;
2. the current-title album identity-source image, falling back to the current
   approved clean profile only when no title source exists;
3. every Founder-selected visual, space, object, styling, or camera reference's
   bound receipt; inspect the exact image or selected cell/crop only when its
   `inspection_action` requires it;
4. the selected Front Planning plan/canvas and current-title package:
   world, wardrobe/material, member/object role, camera/composition, and pose
   or intentional-hold intent.

A candidate remains run-owned and noncanonical until the Founder passes it and
Front Planning integrates its exact current-song consequence. There is no
separate 01A or 02 confirmation artifact.

Record each actual reference by canonical asset id, path, SHA-256, role, order,
preserve locks, discard locks, and intended provider permission. Resolve its
`interpretation_receipt_ids` and `inspection_action` from the active derived
context rather than adding another poster-owned meaning record. The prompt must
make the selected reference consequences observable rather than merely naming
the file or its source.

Use `consume_bound_interpretation` for an unchanged receipt. A model/session
change is not a reopen trigger. For contact sheets, pass only the selected
cell/crop; missing selected evidence is a hold, not a whole-sheet fallback.

## Provider Split

### Grok/native candidate

Use the Front Planning workbench's hash-bound I2I job surface. The job must name
the reviewed prompt path/hash and exact parent asset paths/hashes. It requires
Founder approval for that single job and writes candidates under the run's
`generations/front-planning/grok-roughs/` owner. Do not paste local paths into
the generator prose. Returned images remain candidates until Founder selection.

### Codex image generation

Use only `gpt-image-2`. The track-poster lane has no standing external image
allowlist. Preparing or reviewing a prompt does not approve upload. Keep the
request local unless the Founder explicitly approves the exact task, provider,
prompt, and input files and the repository security policy allows those files.
Character boards, moodboards, contact sheets, and other locally inspected
images are not automatically attachable.

### Manual Grok `/image`

Use only when the Founder explicitly selects the manual route for the current
 job. Attach the approved actual images in their recorded order and paste the
 sealed assigned-owner-authored prompt. Grok does not need or have Codex's
global image-generation plugin; the repository prompt and reference contract
is the shared truth.

## Compact Prompt Rule

The attached image owns appearance. Use one short identity/source sentence,
then spend the prompt on the decisions the generator cannot infer safely:

- exact current-title world and specific space;
- one visible pose/action/hold with weight, hand/foot/object, torso/gaze, and
  garment response when a member is visible;
- camera height, scale/distance, direction/angle, depth, placement, and crop;
- wardrobe/material and unified light behavior;
- which selected reference properties must survive and which must be discarded;
- poster utility, silhouette, and negative-space requirement.

Do not paste an inventory of eye spacing, hair, makeup, jewelry, wardrobe, and
body attributes when the approved image already proves them. Add one exact
attribute only after a recorded generation failure shows that it drifted.

## Selection And Promotion

Inspect each returned candidate as `inspect_current_generated_asset`, then
compare it against identity, bound reference consequences, the active phase's
world and wardrobe/material intent, composition, light integration,
originality, and downstream MV usefulness. Founder selection is explicit. A
selection identifies the candidate that Front Planning must integrate; it is
not canonical promotion. Promote one canonical album/track asset with
path/hash/provenance only after Front Planning confirmation and the explicit
promotion gate. Unselected or unconfirmed candidates remain noncanonical in
their run-owned job and do not enter 01, 02A, or 02B.

Character boards, clean profiles, and other identity-production inputs stop at
this asset-production lane. The passed current-title visual is the only member
appearance image that may continue into the active 02A/02B image route.
