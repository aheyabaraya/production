# IDOL Provider-Neutral Image Generation Director

This skill combines the production designer, still-image director, and image-
prompt designer at the exact owning image checkpoint. It exists to translate
approved creative truth into excellent images, not to redesign its source or
fill graph-engineering fields.

It owns one approved production scope's provider-neutral five-line packet,
provider-conditional image-request preparation, generation intake, and exact
Production Cut pixel review. Pre-02A FP/01/02A work belongs to
`idol-front-planning-development-block` and is not loaded here. This skill does
not authorize paid generation.

## Session And Decision Ownership

- Every worker launch is bound to one current
  `schemas/department-dispatch.schema.json` record and the exact required skill
  revisions, sources, Founder epoch, scope, output path, and stop conditions.
- Create the native Goal named by that dispatch before reading required sources
  or doing task work. Complete or genuinely block that Goal only after the
  return, mechanical checks, and required evidence exist.
- After exact 02A approval, open a fresh just-in-time provider-resolved
  `section_image_motion_worker / worker_high` lineage for exactly one physical
  section. It validates that approved checkpoint, owns this section's 02B
  compile and generation, then applies `idol-video-prompt` through 03V. Pixel
  review is a fresh window on returned artifacts only and does not load this
  generator chat. The reviewer is not a second director. The lineage carries
  neither the pre-02A chat nor another section and may use only the selected
  provider's registered media tools and auth.
- At generated-image inspection, the review window receives exact bytes and
  hashes, not the generation chat. CDD reviews those artifacts and then
  escalates only a reviewed milestone through Overall. Repeated
  Sol/Luna rewrite loops are not an execution route. Self-assessment is not
  PASS.
- 04 edit/QC is a separate execution unit after passed 03V playback.

## Mode Ownership

One packet profile and the same five render-facing lines serve three distinct
owners without transferring creative authority:

- `fp_hero_core`: Front Planning's planning Hero candidate; it is not an 01
  Official Core or a 02A Branch and returns to the active CDD through FP.
- `official_core`: 01's Official Core, including exactly one passed primary
  image. 02A may only import its bytes unchanged.
- `official_branch`: 02A's ordered Branch Cut, compiled and executed through
  the post-02A 02B section lineage.

The compiler branches on the explicit mode and exact source pointer. It may not
reinterpret one mode as another, promote a planning Hero into an Official Core,
or make an Official Core a 02A-authored image.

## Current-Title Visual Binding

The title package is under:

```text
assets/members/album-assets/ALBUM_KEY/TITLE_KEY/**
```

INK supplies no creative content to another title.

The active input route has one combined visual attachment order and no separate
downstream face-only lane. Face-only remains the sole approved upstream
facial-identity source for the member-visual build; retired `no-mic`/`no_mic`
variants are invalid.

- Member visual: appearance, hair, makeup, wardrobe, material, silhouette, and
  body continuity only.
- Background/space visual: section world identity.
- Scene reference: action, staging, still-camera geometry, placement, crop, and
  sequence grammar.

A member visual never forces a readable or frontal face, frontal gaze, pose,
crop, camera, or proportion. A back/silhouette may use it. World/object-only
frames do not.

Consume 02A's `member_visual_applicability` declaration exactly:

- `meaningfully_visible`: require the relevant current-title member visual;
- `visible_but_member_visual_unnecessary`: keep nonempty
  `visible_member_focus`, but prohibit member-visual attachment;
- `not_visible`: keep `visible_member_focus` empty and prohibit attachment.

The author decides this state from the actual frame. Scripts check only its
consistency with the attachment set and never infer it from shot-scale or
body-part vocabulary.

The package is new for every album/title and was built and Founder-reviewed in
Front Planning. A prior album package is never inherited. There is no separate
current-title background/world asset lane. A section/Cut-scoped
`scene_visual_package` is allowed: it keeps `world_look_binding` and still
`composition_anchor` as separate reviewed functions and compiles them together
only after compatibility review. Scene-world truth comes from the passed
Major/Key Screen text and the exact selected scene-reference derivatives; 02A
and 02B preserve those bindings and their declared order.

When Front Planning used `idol-member-visual-identity`, the active member input
is the Founder-passed clean face / upper-body / full-body card. Its face-only
identity source, styling references, and comparison projection remain build
provenance and must not enter 02A, 02B, or image-generation attachments.

## 02B Natural-Language Translation

The five-line grammar, still-camera exact-copy rule, neighbor context, quality
literals, and component split live in
`policies/section-production-02b-pixel.md` heading `## 02B Section Translation And Compile`.
Read that heading to EOF. This skill owns the compile procedure and tools. 02B
does not reinvent camera geometry or neighbor difference.

02B is not a schema dump and not a creative reset. One provider-neutral
`idol_one_cut_one_image.v1` packet serves exactly one named Cut in mode
`fp_hero_core`, `official_core`, or `official_branch`. A human or assigned
model translates that exact Cut using the policy heading's five required
natural-language prompt items. Execution serializes them as the five fixed
labeled lines named there.

Before writing, the assigned author first reads the context pack's complete
PRE-00-rooted full-storyline lineage: immutable original, active full text,
every PRE-00/FP revision, contextual density review, and reference-function
receipts. Then the author inspects the exact named Hero/Core/Branch Cut and its
applicable whole-video, section, planning-cut, and 02A expansion lineage, every
bound current-title asset, and every selected reference derivative. The delta
records those source hashes, the complete binding order, the inspected current-
title asset ids, the storyline-to-prompt component consumption map, and the
authoring owner. A script cannot create this inspection claim or decide that
the storyline was semantically realized.

Use the policy heading's authored components. Across those components, consume
every required storyline category at least once. Do not paste schema ids,
pointers, or hashes into render prose. The compiler may add only the fixed five
line headings, fixed component labels, separators, and punctuation.

The prompt also:

- preserves section, core-cut and branch-cut order;
- preserves the parent Core Cut's intended viewer read and its reason for the
  next governing event without turning either into explanatory render text;
- preserves visible members, action/hold, still camera, composition, and
  selected reference grammar, including the parent Core Cut camera logic and
  the exact Branch Cut realization;
- preserves current-title package identity and combined attachment order;
- uses natural image-render language rather than schema field names;
- contains no ids, paths, hashes, schemas, approvals, process instructions, or
  output paths.

## Non-Prescriptive Teaching Example

This example teaches 02A-to-02B translation. It is noncanonical and supplies no
creative value to a run.

Founder note: `make this branch cut feel more dynamic`.

Upstream 02A compares what can make the still state dynamic from current evidence:
subject/body articulation, object or environment change, placement and depth
relation, material/light contrast, a different branch-cut realization, or another
section-specific carrier. Select the carrier and exact still-camera geometry
there. Do not automatically choose one familiar angle, crop, or house
composition.

At 02B, translate only the selected 02A truth:

```text
Identity reference rule: [current-title member visual role, or none]
Scene intent: [current branch cut's dramatic job]
Visible details:
  background_and_space: [selected current-title world and exact spatial facts]
  still_camera_and_composition:
    camera_height: [authored height]
    shot_scale_distance: [authored scale and distance]
    direction_angle: [authored direction and angle]
    depth_design: [authored foreground, subject, and background depth]
    subject_placement: [authored frame placement]
    crop_negative_space: [authored crop, lead/travel/reveal room, and edge safety when applicable]
    lens_feel: [authored perspective, depth-layer, and focus character]
  lighting_color_material: [authored light, color, and material facts]
Action cue:
  subject_state_or_pose: [authored body or subject state]
  visible_action_or_hold: [authored visible action or intentional hold]
  object_environment_response: [authored response, or null]
Avoid: [current branch cut's named failure conditions]
```

The bracketed roles teach field use. They are not prompt text and must be
replaced by the current Branch Cut rather than copied or filled from memory.

## Generation Preparation

One v12 request owns one packet and one named Cut. Preserve exact prompt hash,
expected output, and
combined attachment order. For every selected Pinterest scene input, preserve
the exact upstream `source_kind` and authored `role` from 02A through 02B and
the image request. This is ordinary main/support metadata, not a new prompt
line or provider-specific rewrite. When the Founder does not name an image
provider, the exact current physical assignment supplies its own native image
surface. The target default is Grok CLI: Grok uses `image_edit` when approved
attachments exist and `image_gen` when none exist. Codex uses only `imagegen`
for an exact current Codex assignment. Cursor Luna is never implied. Those tools, auth lanes,
runtime events, and capability inventories are provider-specific and are never
treated as equivalents. OpenAI API remains locked to `gpt-image-2`, and xAI API
is explicit Founder-authority-only. Every lane pins provider/auth/
profile/version snapshots, exact output, one output, forbidden prompt rewrite,
and no fallback. If the current provider lacks the exact required capability,
HOLD instead of borrowing another provider's tool, auth, model, or session.

The authored reference-role plan has at most four groups:
`character_visual`, `scene_visual_package`, mandatory `motion_reference`, and
optional `prop_reference`. Still/video is media type, not function. One source
may serve several functions, but the same physical bytes appear once in the
combined attachment order. The request exact-carries `section_cohort_id`; it
does not infer a missing role, duplicate a source, or manufacture motion from a
still.

Preparation and local export do not approve paid generation. Stop if the
surface cannot accept every required input.

## Generated Production Cut Review

Pixel-review fields and neighbor inspection live in
`policies/section-production-02b-pixel.md` heading `## Pixel Review And Audio Placement`.
Read that heading to EOF. This window opens on returned artifacts only. Do not
load the generator chat. Self-assessment is not PASS.

Every output is stored in the owning run and receives a byte SHA-256, pixel
dimensions, exact 02A/02B lineage, and the review fields named in that heading,
including Founder PASS/HOLD/REJECT.

Before deciding a row, inspect the exact image and, when they exist, the
immediately previous and next generated Branch-Cut images in same-section
order. Record the judgment in those existing review fields rather than creating
a parallel camera-review contract.

Motion support is evidence for 03V, not a selected move. Do not pass a pixel
defect on the assumption that 03V can hide it, and do not use vocabulary counts
or image-similarity scores as creative review.

Each new branch-cut review binds the exact current 02B packet value hash. An
unchanged passed image/review row may carry forward through an exact prior
review path/SHA, prior row value SHA, and unchanged current packet hash. Carry
the section continuity/repetition row only when the complete ordered packet set
for that section is unchanged; otherwise review that section again.

Before 03V, `idol-production-cut-review.v2` exact-covers the authorized scope
in G-40 order and joins 01's passed Official Core pixels with the current
generated Branch-Cut review. A missing, stale, non-PASS, fabricated, or
out-of-order source row is a HOLD; the aggregator never substitutes an upscale
for the original reviewed pixel authority.

The creative PASS remains bound to the reviewed source bytes. This is not a
free-running post-02B automation and operators do not launch it as a separate
manual continuation. The shared mechanical post-pass opens through either
`idol_review_decision_intake.rb --write` with a complete explicit Founder
all-PASS export, or `idol_g2_delegated_pixel_close_intake.rb --write` with an
exact G2 envelope and Section-Cluster CDD review whose seven applicable grades
are at least 3, motion-anchor grade is 4, and target/message violation plus
material drift are false. Neither script authors those grades or the verdict.
That validated decision may change only the bound
generated review's `founder_review` status and post-pass placement boundary to
their passed values before processing; it does not reinterpret any pixel
judgment. HOLD, REJECT, partial, stale, or non-generated review intakes create
no derivative, change no review status, and open no 03V route. The source remains
untouched; the sidecar
`SOURCE_IMAGE.upscale.json` must validate against
`idol_local_image_upscale_receipt.v1`, preserve aspect ratio, disable crop,
sharpening, and generative enhancement, and produce a PNG whose long edge is at
least 3840 pixels. For a passed Branch row, only that receipt-bound output
enters Audio Production-Cut Placement and 03V. The intake reports
`video_motion_direction` only when an existing ready Audio Production-Cut
Placement also validates; otherwise it routes the continuing section owner to
Audio Production-Cut Placement first. Missing,
stale, smaller, or unbound upscale output is a mechanical HOLD, preserves the
captured Founder decision, and never changes the creative review decision.

This pass-bound local treatment processes every actual generated Branch-Cut
still in the authorized scope. The typed Production Cut review separately
joins those passed Branch pixels with 01's passed Official Core primary images.
For an `official_core` placement row, the original passed Core pixel bytes are
the placement image and no synthetic Core image or local upscale receipt may be
invented. The same mechanical treatment is also available to a non-Branch generated visual, including a current-title member
clean card, only when the active Workbench card explicitly records Founder PASS
for that exact generated image. Face-only and styling inputs, planning or
reference evidence, previously promoted title assets, video, and HOLD/REJECT
cards are excluded. A visual outside the exact typed Production Cut scope
routes back to its owning promotion or stage continuation and never opens 03V
by itself.

## Local Revision

- Pixel defect only: rerun or correct the exact image and its review.
- Render-local correction starts only from an active v12 request plus the exact
  v7 context pack and FP v17 source. The current v8 correction artifact remains
  HOLD for OpenAI until a separately registered Founder-gated correction
  executor exists; the v12 base executor is not implicit correction authority.
- Same-branch-cut prompt wording: compile that exact 02B packet and carry forward
  the unchanged packets.
- Visible action or still view changes: patch the exact 02A branch cut, then
  recompile that packet; carry forward siblings whose branch-cut, core context,
  and neighborhood hashes still match.
- Official Core event, primary image, or Branch need changes: patch the exact
  01 Official Core, then refresh its immutable 02A import and recompile affected
  packets plus any packet whose immediate-neighbor context changed.
- Branch roster changes without a Core-meaning change: patch the exact 02A
  imported Core's Branch roster and recompile the affected packets.
- Section entry/exit, direction, or reference application changes: return to
  the owning 01/02A section and invalidate that section only.
- Target/message/member allocation/title identity changes: return to Front
  Planning.

The post-02A section/image owner returns every passed package or HOLD only to
the active Creative Development Director. CDD reviews exact prompt bytes,
attachments, outputs, and full-size pixels, routes the smallest affected scope
back to FP/01/02A when needed, and sends only a reviewed milestone to Overall.
The worker never bypasses CDD by messaging Founder, Overall, or an earlier
worker directly.

An unchanged section review may carry forward only through an exact prior
review path/SHA, prior row value SHA, and unchanged current section-truth hash.
Whole-artifact SHAs remain audit baselines. Never rewrite or re-review
unaffected upstream artifacts, packets, reviews, or pixels. Refresh a focused
context pack or request only when its transport bytes changed; that refresh is
not new creative authorship.
