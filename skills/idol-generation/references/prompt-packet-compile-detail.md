# Active 02B Prompt Translation And Compile Detail

This reference applies only to:

- `idol_prompt_packet_delta.v1.6`;
- canonical prompt packets `2.6`;
- one exact owning Hero/Core/Branch production scope at a time; Official Branch
  work remains one physical 02A v3.0 section shard.

Historical prompt routes are run evidence only. Do not author compatibility
packets for new or reopened work.

## Purpose

The shared profile translates one passed Cut in the exact declared mode
`fp_hero_core|official_core|official_branch` into natural render language. It
does not redesign the owning Front Planning Hero, 01 Official Core, or 02A
Branch Cut and does not dump schema fields into a prompt. The human or assigned
model authors the translation; the compiler validates and serializes only fixed
labels around those authored components.

Every packet uses exactly this order:

```text
Identity reference rule:
Scene intent:
Visible details:
Action cue:
Avoid:
```

No sixth heading is allowed.

Before authoring, inspect the complete PRE-00-rooted full-storyline lineage
(immutable original first, active full-text version second), then the actual
bytes/pixels for the exact named Hero/Core/Branch Cut and its applicable
whole-video, section, planning-cut, and 02A expansion storyline, every
bound current-title visual, and every selected reference derivative. The
authoring receipt exact-copies all four storyline hashes, the source Cut
contract hash, all binding ids in order, all current-title asset ids in order,
the authoring owner, and the full component order. The model-authored consumption
map assigns the storyline categories across `Scene intent`, the three `Visible
details` components, the three `Action cue` components, and `Avoid`; their union
must cover the required map. A script checks the hashes and coverage only. It
cannot claim inspection, populate a creative component, or approve semantic
realization.

## Creative Translation

Translate the selected 02A truth into fluent image-render prose:

### Identity reference rule

State which current-title member visual assets apply, in attachment order, or
state that no member visual is attached.

`No member visual is attached` maps only to
`visible_but_member_visual_unnecessary` or `not_visible`;
`meaningfully_visible` still requires the passed current-title card, and this
transport statement never directs pose, gaze, crop, camera, or proportions.

- Face-only is the sole upstream facial-identity source. After promotion, the
  packet carries the passed current-title visual and creates no second raw
  face-reference lane.
- The current-title visual may control appearance, hair, makeup, wardrobe,
  material, silhouette, and body continuity.
- It never forces a face, frontal face, frontal gaze, pose, crop, camera, or
  proportion.
- A back view, profile, silhouette, hand/body crop, or unreadable face remains
  valid.
- A physically present but non-appearance-controlling member may use
  `visible_but_member_visual_unnecessary`, preserving `visible_member_focus`
  while carrying no member visual.
- A world/object-only frame must not attach a member visual.
- Never reuse INK pixels, styling, hair, or wardrobe for another title. INK is
  an organization/depth example only.

The compiler validates the structured applicability, policy, and attachment
set. It does not keyword-match the natural-language Identity reference rule,
so an explicit Korean or other non-English statement is valid.

### Scene intent

State who or what is visible, where, and the single image purpose. Preserve the
section, core-cut, branch-cut, and whole-video meaning. Do not add a new plot beat.

### Visible details

Author these internal components before serialization:

- `background_and_space`: current-title world plus exact physical space;
- `still_camera_and_composition.camera_height`;
- `still_camera_and_composition.shot_scale_distance`;
- `still_camera_and_composition.direction_angle`;
- `still_camera_and_composition.depth_design`;
- `still_camera_and_composition.subject_placement`;
- `still_camera_and_composition.crop_negative_space`;
- `still_camera_and_composition.lens_feel`;
- `lighting_color_material`: light, palette, material, wardrobe, and hair facts
  that are actually visible;
- fixed `render_quality`: `4K, high quality, high detail`.

Together they describe the exact still result, including face/gaze only when
actually visible and the selected reference action/composition/staging grammar.

#### Conditional detail-density lens

After the required components are authored, perform one conditional
completeness pass across the exact Cut's shot/angle, identity-bound styling,
props and physical space, lighting, palette/material, and camera rendering.
This pass is a review lens inside the existing components, not a new prompt
heading, fixed output order, provider preset, or permission to reopen 02A.
Add detail only when the current Cut, passed current-title visual, or selected
reference already requires that observable fact; an unsupported surface stays
absent rather than being filled for density.

Use these three lenses only where they improve the named Cut:

- In `background_and_space`, name lived-in or use-history traces only when the
  approved place needs them to read as inhabited, used, maintained, damaged,
  staged, or intentionally untouched. Do not invent decorative clutter.
- In `lighting_color_material`, make a selected material's visible finish and
  its response to light, contact, wear, or environment explicit when that
  distinction affects the image. Do not add gloss, metal, or texture by
  default.
- Recur a selected color across subject, object, light, or space only when the
  current reference/02A continuity already assigns that color a screen job.
  Do not require a fixed number of repetitions, a HEX palette, or a color echo
  on every Cut.

This lens never infers demographic identity, beauty treatment, wardrobe-piece
counts, props, presets, camera devices, or palette from a generic style bank or
sample prompt. Current-run evidence remains the only creative source.

When the approved Branch Cut carries motion-readiness conditions, translate
only the visible prerequisites into these existing fields: action axis/screen
direction, lead/travel/reveal room, separated or deliberately flat depth
layers, a visible path/threshold/occluder, crop/edge safety, and the continuity
anchor. These details must improve the still composition itself. Do not add a
new component or a non-visible promise about future motion.

Do not write temporal camera movement, speed, easing, exact route, reveal
timing, or stop. 03V owns that after passed pixels exist.

### Action cue

Author `subject_state_or_pose`, `visible_action_or_hold`, and
`object_environment_response`. The last value may be `null` only when no
object/environment response exists. Use physically explicit states instead of
vague temporal labels.

Avoid standalone words such as `landing`, `endpoint`, `final state`, `final
frame`, or `arrived` when they can make the image model invent a pose or
composition. If a terminal state matters, name the exact feet, weight, hands,
torso, gaze, object contact, material reaction, and surrounding space.

### Avoid

Write only useful image guards:

- identity or title-package drift;
- reference action/composition drift;
- unwanted frontal portrait bias;
- anatomy, proportion, hand, object, text/logo, or extra-subject defects;
- illustration/3D/glossy-AI drift when live-action realism is locked;
- scene-specific reject facts.

Do not include ids, paths, hashes, schema/profile names, approvals, manifests,
gate language, or process instructions in render-facing text.

## Reference Bindings

The combined visual attachment order may include:

1. smallest Cut-relevant current-title member visual subset, if a member is
   meaningfully visible;
2. governing scene or sequence reference derivative;
3. supporting component reference when required by the Cut.

There is no separate background/world attachment lane.

Each binding keeps canonical path, SHA-256, role, order, inspection state, and
preserve/discard locks in metadata. A Pinterest binding also keeps the exact
upstream `main_reference` or `supporting_visual_reference` `source_kind`; 02B
and generation preparation exact-copy it without a provider-specific rewrite.
Render prose expresses the visible result, not the local path.

`visible_member_focus` and `member_visual_applicability` are separate. A
nonempty member focus may carry zero member visuals only when the author
declares `visible_but_member_visual_unnecessary`; `not_visible` requires an
empty focus, and `meaningfully_visible` requires at least one selected
current-title member visual. The compiler verifies those declared transport
relations without making the creative visibility judgment.

Every album/title builds and Founder-reviews its own package in Front Planning.
Never inherit a prior album package. Omitting or replacing an applicable passed
current-title background/world asset requires the exact upstream
Founder-approved exception.

A sequence sheet is navigation and ordered-flow evidence. Each selected
cell/crop travels as its own derivative; never attach a whole contact sheet as
a fallback for missing selected frames.

For `full_scene_direct` or `sequence_direct`, retain selected action, collision,
body/object route, world/prop effect, subject placement, crop/negative space,
still-camera geometry, and ordered grammar. Replace only current-title member
identity, selected-song timing, or explicitly discarded elements.

If an execution surface cannot accept a required binding, HOLD. Do not drop the
image, replace it with a vague text summary, or change its order.

## Delta Authoring

One v1.6 delta covers one physical section shard. A first compile exact-covers
its 02A Branch Cuts. A local revision may name only changed packets when it also
binds an approved `carry_forward_source_02b`; omitted packets are exact-copied,
never regenerated or rewritten. Each `direct_prompt_revision` binds:

- parent Core-Cut and Branch-Cut pointers/hashes;
- immediate branch-sibling and same-section core-neighborhood context hashes;
- current-title member-visual set/order;
- visual-reference set/order;
- expected output path;
- explicit Founder locks;
- model/human-authored structured five-field `prompt_blueprint`;
- an exact authoring-inspection receipt covering the Branch Cut, every visual
  binding, every current-title asset, and every creative component;
- true preservation assertions.

The author may improve render wording only while preserving the passed 02A
image result. A change to member ownership, action, still view, composition,
reference application, section meaning, or branch-cut roster returns to 02A or its
upstream owner.

## Compiler Boundary

The active compiler consumes v1.6; operationally it consumes one v1.6 delta and may:

- validate paths, hashes, pointers, order, exact coverage, and required fields;
- exact-copy bindings;
- add only the fixed five headings, component labels, separators, and
  punctuation while serializing already-authored components, including the
  author-supplied fixed quality literal without alteration;
- compare section-invariant, entry/exit-boundary, core-cut context,
  exact-branch-cut, immediate branch-sibling, and same-section
  previous/current/next core hashes;
- carry an omitted packet only when all of those applicable local hashes still
  match the current 02A;
- emit one noncanonical section packet;
- refuse incomplete or stale inputs.

It may not:

- author, infer, paraphrase, repair, pad, or score creative prose;
- claim that a source or pixel was inspected;
- infer identity or reference inputs;
- invent a neighboring cut;
- add camera movement;
- add a sixth prompt field;
- silently remove a binding;
- merge an unreviewed section.

After Founder PASS for each numbered section artifact, the deterministic merge
preserves 02A section order and emits canonical `2.6`. Every active section
must carry current local lineage. Historical packets without that lineage are
evidence only; the active route provides no compatibility fallback.

## Founder Review

For every packet, the review unit shows:

1. target/message and section-flow summary;
2. section and parent core cut;
3. ordered branch-cut position and its distinct contribution;
4. exact current-title and scene-reference inputs needed for judgment;
5. the five required prompt items in their fixed five-line serialization;
6. expected output path;
7. PASS/HOLD/REJECT.

The Founder reviews the intended image before generation and the actual pixel
after generation. Structural validation never equals creative approval.

## Generation Handoff

One execution request owns one packet. Preserve:

- exact full prompt hash;
- combined attachment order;
- expected output path;
- highest available quality and maximum supported dimensions for the selected
  aspect ratio;
- `gpt-image-2` for OpenAI API generation.

Preparation is not paid-generation approval. A section worker receives only its
section packet set and may dispatch disjoint packets in bounded parallel.

## Local Revision

- Wording-only render correction -> patch the exact 02B packet and carry
  unchanged sibling packets.
- Same Branch Cut but changed visible action/still view -> patch the exact 02A
  Branch Cut and recompile that packet.
- Official Core event, primary image, or Branch need -> patch the exact 01
  Official Core, refresh its immutable 02A import, and recompile packets whose
  current/adjacent Branch or Core-context hash changed.
- Branch roster without a Core-meaning change -> patch the exact 02A imported
  Core's Branch roster and recompile affected packets.
- Section boundary, scene, or reference application -> return to the owning
  01/02A section and invalidate that section.
- Target/message/member allocation/current-title identity -> return to Front
  Planning.

An unrelated metadata-only whole-file change carries every locally matching
section and packet. An unchanged 02A creative-review row carries only with its
prior review path/SHA, row-value SHA, and unchanged section-truth SHA. Never
rewrite or re-review unaffected upstream truth, neighboring sections, prompt
packets, or generated pixels.

## Final Check

PASS only when:

- the prompt is a natural translation of the exact named Cut in its declared
  `fp_hero_core|official_core|official_branch` mode;
- the five headings and order are unchanged;
- the authoring receipt exact-copies the source Cut contract hash, visual
  binding order, and current-title asset order;
- every structured Visible details and Action cue component was directly
  authored after inspection;
- current-title visuals are conditional and do not create portrait bias;
- direct scene/sequence grammar is preserved;
- still-camera geometry is concrete;
- the conditional detail-density lens adds only source-supported lived-in
  traces, material finish, or color recurrence and leaves unsupported detail
  absent;
- applicable video-bearing frames preserve visible motion-ready room, layers,
  path/crop safety, axis, and continuity anchors;
- temporal camera motion is absent;
- required quality terms are present;
- no internal metadata appears in render prose;
- all inputs and output paths are hash-bound;
- the section review has passed.
