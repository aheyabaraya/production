# Reels & TikTok Posting Template

Use this skill only for **Instagram Reels** and **TikTok** planning/copy around
AURORA-M internal work or Loom public releases. It is a social publishing helper,
not an MV graph-engineering route, generation, edit, upload, scheduler, or analytics runner.

Internal production text keeps `AURORA-M`. Public-facing copy uses **English
only**, group name `Loom`, fan name `Harne` when relevant.

## Current-Source Gate

This skill is a repo-local operating heuristic. Instagram Reels and TikTok
algorithm behavior, recommended frequency, hashtag effects, trending-audio
effects, upload limits, and metric weighting must not be described as current
fact unless the founder approves a current-source check for this task.

Without that approval, label platform claims as `local heuristic` and write only
from repo-local release/source material.

The current approved package, master, cutdown, or clip is the only source for a
title, member, prop, action, movement, camera/composition phrase, caption hook,
or title/member hashtag. Poetic wording must still resolve to **brand-core or
run-locked message** sources — not free invention. Never carry a prior run's
example nouns or sentences into a new post.

## Read / Write Contract

- Allowed outputs: draft Reels/TikTok copy, cover-text options, hashtag sets,
  schedule suggestions, manual-upload checklists, and run-owned
  `publishing-plan.md` entries when explicitly requested.
- Forbidden outputs: direct upload, scheduling, publishing, platform API sync,
  external account access, or analytics ledger mutation without explicit founder
  approval.
- Registry behavior: follow `wiki/social-automation-system.md`; this template
  alone does not register outputs.
- Founder gates: public release approval, platform publish approval, external
  sync approval, and current-source approval when latest platform claims matter.

## Business surface and publish order

Loom's account portfolio still connects **idol MV**, **CF work**, and
**production evidence**, but one post does not need to explain all three.
Instagram/TikTok copy leads with the current screen and its locked message, then
keeps production credit compact through the required disclosure and short stack.

```text
1) X first (skills/x-posting-template)
2) TikTok (+ YouTube Shorts via idol-social-metadata-upload)
3) Instagram manual
```

Do not schedule IG/TikTok ahead of the same-batch X publish unless Founder
explicitly locks an exception.

**Always include:** `https://loom-signal-deck.vercel.app/`

## Content inventory and per-work bank

| Type | Source | Platform use |
| --- | --- | --- |
| `work_root` | CF final or approved MV cutdown | TikTok/Reels anchor for one completed work |
| `derived_clip` / `hook_loop` | Distinct **3–8s** hook, member beat, object/world beat, or loop from the same work | TikTok/Reels; the same video bank also feeds YouTube Shorts through `idol-social-metadata-upload` |
| `member_still` / `member_carousel` | Approved current-title member stills, board stills, or portraits | Instagram only by default; not TikTok/Shorts filler |

Plan one work as **one work root plus 2–4 distinct derived clips over later
days**. Do not collapse one package into one post, and do not repeat the same
full cut with cosmetic caption changes.

TikTok and YouTube Shorts are video-first. Image-only rows are not their
default. Instagram may use Reels, member stills, and carousels.

The exact approved media bytes from an X `derived_clip` may be reused on
TikTok, Instagram Reels, and YouTube Shorts. Reuse of media is allowed; copying
the X caption is not. Re-author the hook, message, and metadata for the target
platform.

**Cadence is a local planning heuristic, not a platform guarantee:** about
1–2 TikTok/Shorts clips per day is sufficient when distinct clips exist. Do not
add image filler to imitate X's 2–3-post heuristic.

## Caption kernel

Every caption includes, in English:

1. **Poetic idol / scene hook** — from brand core or run-locked message
2. **Message line — required** (what we want the viewer to receive)
3. **Subject frame — required when CF or category/form-led** (and recommended
   on derived clips that still read as that category): one line naming genre,
   product class, occasion, form, or mood **as the screen actually shows**.
   Category language only — not an official brand claim. Pair the same words
   into subject/product-class hashtags.
4. **Member “doing now” line** when a named member is meaningfully on screen,
   sourced from the brand card or run-locked visible action
5. **Members / track / CF label** when relevant
6. **Claim guard** when a real brand is visually readable on a spec CF
   (`Spec concept. Not an official {Brand} campaign.`)
7. **AI-made disclosure — required** — `AI-made with Grok and GPT.`
8. **Short stack — required** — prefer `GPT image → Grok Imagine → Grok Build`
9. **Signal Deck URL — required**
10. **Tags** per platform rules

**Message vs subject_frame:** message = receive meaning; subject_frame = what
kind of content this is (battle-royale mood game film, eyewear fashion film,
chorus-hook cut). Do not invent a category the media does not support.

These Non-X rules do not inherit X intensity 0: the message, stack, and Signal
Deck remain present. Process stays a short credit line, not a full prompt or
board-lock explanation.

## Fast Route

1. Confirm the batch already has or will have an **X-first** packet.
2. Confirm asset lane: work root, distinct 3–8s derived clip/hook loop, or an
   Instagram member still/carousel.
3. Confirm platform intent (IG aesthetic vs TT discovery).
4. Keep TikTok full-version exclusion unless Founder changes it.
5. If a named member is meaningfully visible, source one plain English
   `{Member} — what they are doing now` line from the brand/run lock.
6. Pull poetic hook + message from brand/run locks; draft **subject_frame**
   when CF/category-led; draft stack + URL + tags that match that category.
7. For shared X media, rewrite rather than copy the X caption.
8. Plan row fields: see Minimum Posting Plan Rows.


Optional: `#{TITLE}` `#{MEMBER}` `#Harne` `#IdolEdit`

**Subject frame + product-class tags (CF + MV)** — when the clip has a clear
advertised subject or category:

1. Write **subject_frame** in the caption body after the message (one line,
   category language, screen-true).
2. Mirror those words as **hashtags** using product class / occasion / form only
   (e.g. `#eyewear`, `#lipstick`, `#fashionfilm`, `#gamead`, `#battleroyale`,
   `#AIMV`).

**Never** real brand names, retailer tags, or partnership tags unless the
Founder explicitly locks a real claim. Spec CF must not tag or frame as an
official brand campaign. Full tag rule lives in
`skills/idol-social-metadata-upload/SKILL.md` (shared upload owner).

Do not default `#AURORAM`, `#fyp`, `#viral`, `#trend`.

### Wrong-direction signals

- Missing Signal Deck URL, message line, or `AI-made with Grok and GPT.` disclosure
- CF/category-led clip missing **subject_frame** or pairing only tags with no body frame
- subject_frame that invents off-screen genre or claims official brand ownership
- Dry tool-only caption with no idol/message
- Full prompts on IG/TT
- Member-led row with no sourced “doing now” line
- One work represented by only one row when approved distinct derivatives exist
- X caption copied onto TikTok/Instagram without retargeting
- Image-only TikTok filler used to chase X cadence
- IG/TT before X in the same batch without Founder exception
- Korean captions; invented slogans not grounded in locks
- Identical caption clone across X / TT / IG

## Common release handoff

Both rows may live in the same run-owned `platform-posts*.jsonl` batch:

- TikTok is selected by `idol_platform_draft_upload.py` and may become
  `uploaded_tiktok_inbox` after Founder-approved API upload.
- Instagram is deliberately skipped by that uploader and remains a
  `manual_upload_package`; completion requires a separately observed manual
  post URL/id.

YouTube Shorts rows live in the same batch but remain owned by
`idol-social-metadata-upload`; do not create a separate Shorts template skill.
They reuse the TikTok video bank and carry a slightly fuller description.

The TikTok inbox result is a draft-transfer fact, not a public-post fact. Keep
the caption and hashtags in the common row because the inbox upload API does
not guarantee caption prefill. If credentials are missing or expired, use
`python3 scripts/idol_tiktok_oauth_reauth.py --open-browser`; enter app secrets
only in its localhost page and never in chat.
The current verified test baseline is the 2026-07-29 Sandbox Desktop result
`CF_COSMETIC_TARGET_DISCOVERY_001-TT-20260728-001` with
`draft_status=uploaded_tiktok_inbox`.

## Quality Check

Before returning or writing a plan, check:

- English only; poetic hook (not dry tool-speak as hero line).
- Message line present and drawn from brand/run lock.
- CF/category-led rows include **subject_frame** after message (screen-true category language).
- Member-led rows include a sourced plain English “doing now” line.
- Members/track/CF named when on screen.
- `AI-made with Grok and GPT.` present; stack short line present; Signal Deck URL present.
- New rows prefer `GPT image → Grok Imagine → Grok Build`.
- First 1–3 seconds have a visible hook.
- Work plan can carry one root plus 2–4 distinct 3–8s derivatives over days.
- Shared X media is allowed; X/TT/IG captions are not clones.
- TikTok/Shorts stay video-first; no image filler to match X cadence.
- IG and TikTok captions are not identical clones of each other or of X.
- TikTok is not a full-MV dump by default.
- No full image/video prompts on IG/TT (those live on X).
- `#fyp` / `#viral` not default; public name is `Loom`.
- Subject/product-class tags present when CF/category-led; **no brand tags**; tags match subject_frame.
- Same batch respects **X first**.
