# Provider-Neutral Studio Kernel And Launch Command

Status: active
Scope: every Overall Director, Creative Development Director, Edit Director,
department worker, Song Room, Member Visual Identity owner, and post-02A
section-owner launch
Authority: `AGENTS.md`, activated policies, the exact selected skill-load
profile/checkpoint, and the complete owning skill remain authoritative

## Purpose

This is the shared Studio Kernel for Cursor, Grok, or another registered
provider surface. Provider adapters transport the same per-assignment role
binding and launch command; they do not rewrite its creative or studio
authority. No global provider mode or model selection establishes authority.

One launch has three layers:

1. **Registered Department Recipe** — the repeatable job method already written
   in the exact owning `SKILL.md`, its linked reads, and the selected
   `automation/harness-skill-load-profiles.yaml` profile/checkpoint. Reference
   discovery, source eligibility, comparison floors, image-prompt translation,
   generation inspection, output shape, review route, and ordinary HOLD rules
   belong here and are reused rather than rewritten for every assignment.
2. **Director-authored Current Assignment Delta** — what this exact run,
   section, source set, and checkpoint must solve now. The assigning director
   writes this only after reading the current frontier and bound evidence. It
   names the present gap, the decisions the worker may make, the task-specific
   work that the registered recipe does not already say, and the current-work
   proof required for review.
3. **Mechanical Dispatch Envelope** — ids, roles, scope, paths, hashes,
   permissions, selected profile/checkpoint, output ownership, return route,
   and wake/stop conditions. A tool may exact-copy these values, add the fixed
   headings below, and hash the final bytes. It may not choose the Department
   Recipe, write the Current Assignment Delta, summarize current evidence, or
   claim creative approval.

The launch command is therefore reusable without becoming a generic creative
prompt. Stable work stays stable; current creative judgment stays current.

## Who Authors And Who Reads

- The Overall Director authors the Current Assignment Delta for CDD startup and
  any worker it directly owns.
- The Creative Development Director authors it for Song, reference, identity,
  and pre-02A development workers.
- The Edit Director authors it for edit shards.
- The receiving role's first runtime action is to open the native Goal from
  `launch.goal_contract` and record its provider-native identity. The mechanical
  coordinator then verifies the complete selected source closure to EOF and
  builds the exact `idol-role-context-pack.v1`; the receiver applies that pack,
  the rendered Current Assignment Delta, and the named current creative sources
  before work. The pack replaces broad receiver instruction rereads and is not
  an additional layer. If that runtime cannot
  open an auditable Goal, return `goal_surface_unavailable` HOLD before work.
- A valid current-run v3 Founder-feedback sidecar may contribute only the
  pack's exact role/profile/stage/section-matching compact quality patterns:
  short reason, recurrence count, bounded positive/avoid/action/review signals,
  applicability, evidence-rollup digest, and source sidecar pointer. Directors
  receive the current-run review view; workers receive exact matching section
  rows. Never load the raw Founder wording or full closure into the runtime
  command. This advisory semantic edge is not a lock, gate, PASS, or promotion.
- A provider/model name is transport metadata only. Canonical command prose
  uses `overall_director`, `creative_development_director`, `department_worker`,
  `section_owner`, `edit_director`, or `edit_shard_worker` authority. Each
  attempt binds exactly one `studio_role` and `assignment_key` to owner,
  parent lineage/session, exact scope, adapter/runtime surface, capability
  receipt, Goal contract, output owner, return recipient, and stop/wake route.
- The shared contract covers logical operation, not provider-tool identity.
  Director/worker roles, physical sharding, Goal admission, successor/CAS/rollback,
  return, and review are equal across Cursor and Grok. Provider-native tools,
  auth lanes, event shapes, and capability inventories remain separately
  registered: Cursor supplies exact text-model sessions while Grok image work
  uses `image_gen`/`image_edit`. An omitted image provider resolves only to the
  exact current Grok Section owner's native surface; Cursor Luna image and APIs
  require explicit Founder
  selection. A missing capability returns HOLD and never borrows another
  provider's tool, auth, model, or session.
- A bounded department worker uses an internal subagent by default. It opens a
  separate Founder-visible physical assignment session only when the exact
  run-route row sets `founder_visible: true`: a separate Cursor CLI chat or a
  separate Grok native/CLI-style session surfaced like a terminal. Both
  topologies use the same Dispatch, Goal, model/effort, authority, review, and
  quality contract; visibility grants no promotion authority and neither
  topology may mix with the parent Director session. CDD dispatch, review, and
  ordinary FP/02A multi-leaf work must open Grok `spawn_subagent` helpers to
  the floor in `automation/harness-execution-contract.yaml`
  `session_route.department_worker_execution_topology.parent_scoped_helpers`.
  Those helpers are not physical terminals. Image section owners stay physical
  post-02A sessions.
- For Cursor CLI transport, create and hash the external assignment Goal record
  before launch, verify the authenticated account model catalog and exact CLI
  model argument, then bind the init display, terminal result, request id, and
  stable session id. Resume must return the same session id.
- For Grok ACP, invoke `/goal` with the exact objective from
  `launch.goal_contract` as that first action. The native `goal_updated` event
  must prove native Goal id, exact objective (or an exact-objective match), and
  state. The adapter attestation envelope records the raw-event digest, exact
  goal-text SHA-256, immutable assignment key, attempt/dispatch ids, runtime
  surface, and timestamp. A model-written id, chat heading, or copied status
  is not a Goal receipt; a missing or mismatched event plus attestation is
  `goal_surface_unavailable` HOLD. Other registered adapters require
  equivalent auditable native Goal evidence and an adapter attestation.
- Goal state is interpreted through the registered provider adapter. Cursor
  keeps the host-owned external Goal record active through work. Grok may
  emit `complete/goal_completed` at the durable terminal of the exact `/goal`
  admission prompt. In a successor preflight that terminal means only
  `successor_admission_complete`; the logical CDD assignment remains
  read-only until the shared session router commits A->B. Neither Goal event
  is creative PASS, CDD completion, canonical promotion, or Founder PASS.

Before authoring the Current Assignment Delta, the director must inspect:

1. the exact Founder request and verbatim explicit locks;
2. the current canonical frontier, decision epoch, owner, and review state;
3. the selected target/song/audio/whole-video and assigned-section facts needed
   by this task;
4. every current source or output whose pixels, playback, or bytes control the
   assignment;
5. the selected Department Recipe and its exact checkpoint;
6. the smallest unresolved decision and the legal next checkpoint.

If those facts are incomplete, write a bounded HOLD command instead of filling
the gap with a generic task.

## Department Instruction Delivery

For the Workbench Grok v8 Department text route, select
`launch.instruction_delivery: role_context_pack` in the immutable prepared
attempt. After native Goal verification and launched Dispatch persistence, the
host freezes the launched bytes and builds the exact-node context packet through
`scripts/idol_department_context.rb`. Its worker prompt preserves the complete
original twelve-block command verbatim and supplies the projected instructions.
The adapter includes the actual packet receipt in the sent prompt hash.

A projected return carries `role_context_receipt` and `skill_revisions: []`.
The worker supplies its real application time; the host verifies the packet,
source, Goal, session, owner, epoch and timing before report bytes are written.
This acknowledgement is transport evidence, not a claim to have read full files
or a skill-application verdict. Requirement claims and Director review remain.

An attempt without that explicit mode retains the v8 full-EOF return contract.
Do not convert its evidence, silently fall back, or infer this capability for
Cursor, media generation, another runtime, or Graph v2. Missing projected
transport is a HOLD. Director review retains the read closure below.

## Fixed Twelve-Block Command

Every rendered launch command uses these exact Markdown H2 headings in this
order. The headings and repeated transport values may be assembled
mechanically. The prose marked **current** must be authored by the assigning
director from the inspected current work.

```text
First runtime action: open the registered Goal from launch.goal_contract and
record its provider identity before Role Context Pack validation or creative work; Cursor
creates the external Goal record before CLI launch, while Grok ACP captures
`goal_updated`, with the exact objective hash and assignment-key evidence.

## 01 Dispatch Identity
## 02 Role And Authority
## 03 Current Creative Job
## 04 Exact Scope And Non-Scope
## 05 Input Pointers
## 06 Skill Route
## 07 Required Work
## 08 Output Contract
## 09 Quality Proof
## 10 Return-Ready Conditions
## 11 HOLD Stop And Split Conditions
## 12 Return And Wake
```

Block ownership is:

| Blocks | Source | Rule |
|---|---|---|
| 01, 02, 04, 05, 06, 08, 10, 11, 12 | Mechanical Dispatch Envelope plus registered profile | exact-copy only; task-specific HOLD text may be director-authored |
| 03 | Current Assignment Delta | director-authored every attempt |
| 07 | Registered Department Recipe plus Current Assignment Delta | cite/bind the reusable recipe; author only the current extra work, order, or decision gap |
| 09 | Registered professional gate plus Current Assignment Delta | reuse stable proof categories; author the exact current-work evidence the return must show |

Do not paste the complete owning skill into Blocks 06 or 07. Bind its exact
path/revision/SHA-256 in the dependency inventory, then bind the validated Role
Context Pack and its pack/source-set digests. The projector verifies the whole
source to EOF; the receiver applies only the exact projected content and named
creative sources. Repeating the whole skill creates drift and does not prove
application.

The mechanical envelope carries the immutable role-assignment binding, selected
provider adapter and capability receipt, `launch.goal_contract`, and native
Goal event plus adapter-attestation fields. These values may be exact-copied
and hashed; no adapter may infer, paraphrase, or replace them. Goal creation
and its provider-native updated event are runtime compliance receipts, not
creative or Founder approval.

The mechanical envelope also carries a stable `requirement_manifest`. Give
each Founder instruction, required skill, policy, contract, schema, output,
quality gate, HOLD rule, and Goal duty its own id, source locator, affected
scope, expected target, and evidence type. Do not collapse several instructions
into one generic “follow everything” row.

Current priorities must survive every handoff as executable emphasis, not as a
bare instruction to read a skill. Exact-project each required Founder row into
Block 03, each scoped method/output/HOLD row into Block 07, and each quality or
Anti-Flat proof row into Block 09, using the stable requirement id and its
source locator, affected scope, expected target, and evidence type. The worker
must close the same ids in `worker_fulfillment_claims`; the recipient Director
must independently close them in `director_review.requirement_results` against
the exact returned bytes. Missing, merged-away, genericized, duplicated, or
self-asserted coverage is a HOLD. Keep the owning skill hash-bound and fully
verified by the projector, but do not duplicate its whole prose or turn its
dependency inventory into a second receiver read list.

## Non-Executable Authoring Skeleton

This skeleton shows what the assigning director writes. It is not a launch
command until every placeholder is replaced from current-run evidence and the
exact Dispatch Envelope is bound.

```text
First runtime action: open the native Goal from launch.goal_contract and record its id before Role Context Pack validation or creative work.

In that fixed directive, `id` means the registered provider identity: the
Cursor external Goal-record hash plus CLI session id, or the Grok Goal `id`.
Never accept a chat heading or model-written surrogate.

## 01 Dispatch Identity
<dispatch id, lineage, immutable attempt, provider-neutral studio role,
assignment key, adapter/runtime capability receipt, and Goal contract>

## 02 Role And Authority
<assigned owner, director owner, promotion boundary, permitted decisions>

## 03 Current Creative Job
Resolve <one current named gap> for <exact run/section/checkpoint>. Preserve
<current locks and governing facts>. The result must change or clarify
<current screen/song/edit consequence>; it must not reopen <unaffected truth>.

## 04 Exact Scope And Non-Scope
<exact included and excluded sections, artifacts, decisions, and paths>

## 05 Input Pointers
<exact current source ids, paths, hashes, locators, and required inspection>

## 06 Skill Route
Use <profile id.checkpoint id> and apply <exact Role Context Pack id, pack
digest, source-set digest, selected fragments, and pointer-only structural
preflights>. The broad skill/read closure is the mechanically verified
Department Recipe dependency inventory, not a second runtime read list.

## 07 Required Work
Follow the registered recipe. For this attempt, additionally <task-specific
comparison, decision, translation, correction, or sequencing work>. Do not
repeat <already closed work>.

## 08 Output Contract
<bounded output kind, exact paths, count, ownership, and manifest rule>

## 09 Quality Proof
Return the recipe's stable evidence plus current proof that <named dependency,
state change, source-to-screen delta, pixel/playback fact, or edit consequence>
is resolved. Generic confidence or a self-assertion is not evidence.

## 10 Return-Ready Conditions
<exact structural, evidence, review, and checkpoint conditions>

## 11 HOLD Stop And Split Conditions
<missing/stale/conflicting inputs, authority stop, and legal split request>

## 12 Return And Wake
<recipient, allowed event kind, compact pointers/hashes, registered Goal
identity/state, matching Cursor CLI runtime receipt or Grok goal_updated event
plus adapter evidence, no raw commentary>
```

“Find good references,” “make an image,” “improve the scene,” or “follow all
skills” is not a Current Assignment Delta. The reusable Department Recipe may
define how reference research or image work is performed, but the current
command must still name what this assignment is solving and which current
evidence will prove it.

## Same-Session Checkpoint Progression

A legal next checkpoint may continue in the same physical session and lineage.
This is normal continuation, not a successor-session rollover, only when all of
the following are true:

- the current attempt returned and its declared recipient completed director
  review;
- any required Founder decision or intervention receipt is recorded and bound;
- the current owner, scope, and output paths remain unambiguous;
- the immutable `studio_role` + `assignment_key`, provider adapter/capability
  receipt, and native Goal/`goal_updated` evidence remain bound to the attempt;
- the next checkpoint exists in the selected provider-neutral profile and its
  activation conditions are satisfied;
- a new immutable attempt is prepared with the next checkpoint's exact
  skill/read set, refreshed source hashes, and a fresh input digest;
- no stage, Founder, paid/external, pixel/playback, or owner gate is skipped.

The director may prepare the next command from that checkpoint without asking
the Founder to restate already settled input. It may not infer a PASS, jump to
an arbitrary later checkpoint, widen scope, or silently replace the owner.

CDD may progress through legal checkpoints inside its one existing physical
session. A physical successor is permitted only on the registered Boot Pack v3
and session-router route: first Founder confirmation, immutable hash-equal
checkpoint and no-rollover check, fresh zero-turn read-only successor, exact
seven-answer preflight, registered Goal-admission receipt, second Founder
confirmation, and exact A->B writer compare-and-swap. Embedded Workbench may
use its native bridge; direct Cursor-CLI/Grok-CLI operation uses
`idol-cdd-session-router-state.v1`. Every prompt/resume/dispatch/review/write
must be authorized against the current state SHA and generation. A later
failure atomically retires B and reactivates A. This changes only physical
session authority; it does not rewrite HTML, review-board, canvas, storyline,
Section, or canonical creative bytes. A provider surface without equivalent
admission, CAS, access-denial, and rollback proof remains `HOLD`.

## Return Review

Close three separate verification layers; none substitutes for another:

1. **Mechanical receipt:** deterministic checks verify fields, cross-fields,
   paths, hashes, registry and consumer versions, lifecycle order, Goal order,
   and requirement coverage. They never judge creative adequacy.
2. **Worker fulfillment claim:** the worker closes every requirement id as
   `applied`, `held`, or legally `not_applicable`, points to exact output
   evidence, explains the application, and reports the provider-native Goal identity and return state.
   A self-claim is evidence for review, not acceptance.
3. **Director fulfillment review:** after acquiring the single-flight review
   lease, the recipient Director reviews the validated Role Context Pack, the
   named current-run creative sources, the same checkpoint closure cards, and
   the exact returned bytes. The projector already verified the registered
   source closure to EOF. In the current v8 Director return contract,
   `reviewer_read_closure` still requires actual full reads of the selected
   skills, linked modules and semantic-review sources during the review lease.
   A worker Pack receipt cannot replace that Director evidence. The Director
   records an independent
   judgment for every requirement id and applies the fixed creative rubric: Goal
   pursuit, Founder coverage, skill application, schema/contract conformance,
   current-gap resolution, required outputs, observable specificity,
   source/pixel grounding, storyline preservation, locks/unaffected truth, and
   honest completion state. A worker claim, schema/path check, or historical
   receipt is evidence-only and is not PASS. Overall reviews the curated
   milestone and whole-film consequence; it does not recount mechanical
   presence rows.

Workers may return in parallel and mechanical preflight may run in parallel.
One recipient Director must nevertheless review one return at a time in
`dependency_rank -> returned_at -> dispatch_id` order. Do not open the next
return until the prior disposition, Overall promotion or HOLD, single-writer
commit, and baseline refresh are recorded. Overall promotion uses one global
lease. Batch acceptance and batch promotion are forbidden.

The exact input/result digest, reviewer role, owning scope, and Founder epoch
identify a semantic review. Carry a valid receipt forward when those values are
unchanged; a new session, provider, or model is not a re-review trigger. Overall
reviews the recipient Director's curated milestone and whole-work consequence,
not the raw worker checklist again, unless bytes, governing input, epoch,
evidence completeness, owner/scope, or a concrete conflict changed.

Before a successor attempt, resolve its canonical predecessor in the same run
and prove terminal runtime return, recipient review, and Overall promoted/HOLD
closure. `final` and `hold` may close; `authority_request` and `milestone`
preserve the same attempt. Keep dispatch records under
`RUN/work/department-dispatches/` and every output or manifest inside that
album/title/run; never create a global worker lane below `runs/`.

Track review submissions independently from checkpoint `attempt_number`. One
review cycle allows three submissions at most, with the initial return counted
as 1. On a non-accept disposition, the Director must return the complete
observed problem set, exact invalidated outputs, one correction action, and
explicit acceptance criteria together. Submission 2 or 3 opens a fresh native
Goal that exact-copies that correction action and scopes work/output only to the
invalidated paths. That Goal reopens the same section-worker line or session
that authored those paths; do not reassign the whole package to a new random
worker. Preserve all other predecessor outputs as hash-frozen inputs;
do not regenerate them. Same-session correction preserves session and lineage;
new-session correction starts a fresh lineage at attempt one but preserves the
same review cycle and next submission number. Submission 3 may pass, but another
child retry is forbidden; route a remaining failure upstream or HOLD. Session,
provider, model, or Founder epoch cannot reset the counter for the same work
package.

Do not spend a creative Goal or review submission on corroborated transport
drift. Re-hash all prepared launch bindings before creating a worker session.
When one stale hash field disagrees with at least three current-hash receipts
across two independent lifecycle phases, including the latest phase for those
bytes, route it once to the mechanical coordinator's run-local
`department-transport-refreshes/` receipt. Preserve the immutable Dispatch,
all creative bytes, the existing Director review, and the submission number.
If the bound source bytes themselves changed and no such consensus exists,
the recipient Director performs one impact recheck before deciding whether a
targeted creative correction is needed; workers do not bounce the same hash
problem between sessions. Changed output bytes never qualify for this shortcut.

Workers do not create creative grandchildren in either internal or physical
execution. A worker that needs a split returns exact unowned subscopes, sibling
count, disjoint paths, shared boundaries, and risk. Its recipient Director owns
review and any sibling Dispatch creation.

Only after all three layers pass and both leases close may the normal CDD
review, Founder gate, or next same-session checkpoint proceed.
